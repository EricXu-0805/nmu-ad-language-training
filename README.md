# 南医大 · AI 语言沟通训练系统 — platform

面向轻中度认知障碍老人的 AI 语言沟通训练研究平台。当前形态是**自有服务器持久化 + 可选云端 AI 增强**：数据库、录音原件、导出包和 TTS 缓存在课题组控制的服务器上；配置百炼 API Key 后，部分训练话术、受试者音频和回答文本会按下文边界发送给第三方云服务处理。

> **当前仅限开发、模拟预演和受控技术验证，不得据此开展正式受试者入组或正式研究数据采集。** 配置 API Key、部署到课题组服务器或自动化测试通过，都不等同于伦理、临床内容、云数据处理和目标设备验收通过。

非技术用户与负责人请先看 [`docs/acceptance/2026-08-12/README.md`](docs/acceptance/2026-08-12/README.md)，不要从测试通过直接推断“已经可以给患者使用”。

## 数据流真相

浏览器只访问本平台同源接口；是否调用第三方云服务由后端配置决定。`DASHSCOPE_API_KEY` 存在且相关引擎使用 `auto` 时，当前默认数据流如下：

| 能力 | 离开自有设备/服务器的数据 | 明确不应发送的内容 | 无 Key 或云失败 |
|---|---|---|---|
| 云 TTS（generic/manual） | 题库、脚本和固定 UI 白名单中的话术文本；云端返回合成音频，服务端可缓存 | 受试者编号、姓名、画像、自由回答等白名单外文本；守卫拒绝后不调用云端 | **本行只讲 generic/manual**：本地 Piper；仍不可用则回退设备系统语音或静音。**exact/autopilot 不适用此列**：缺 Key、云调用失败或 strict WAV 校验不通过时一律明确失败/暂停并如实记账，**绝无 Piper 或浏览器系统语音回退**（详见"音色链路"） |
| 云 ASR | **受试者原始回答音频**，以及由题库目标词、可接受表达等组成的识别上下文 | 当前请求不附带受试者编号/画像，但声纹和回答内容本身仍属于受试者敏感数据 | 返回降级状态，由研究者人工转写 |
| 云 LLM 初评 | 题目类型、目标词、可接受表达、相关词，以及 ASR/人工确认的**受试者回答文本** | JudgeInput 结构和运行时守卫禁止画像、姓名和受试者编号进入判分请求 | 回退规则判定；无确定口径的环节交人工复核 |

TTS 白名单只能证明“没有把患者字段混进 TTS 文本”，不能证明整个平台“不接触云端”。尤其是 ASR 会上传原始声纹，LLM 会处理回答文本。云服务的日志、保留期限、区域、二次使用和删除能力由供应商条款及课题组账号配置决定，不能由本仓库单方面保证。

**“再说一遍”重播的准确口径**：同一逻辑题位第一次显式重复请求时，服务端发行一条**新的** TTS 命令，其 canonical `payload_json` 是前驱命令 `payload_json` 的逐字节副本，因此冻结的 `speech_text` 完全相同；随后这条新命令仍然走当前的 Qwen-only exact 合成与缓存链路。`source_payload_sha256` / `replay_source_payload_sha256` 都只是该 `payload_json` UTF-8 字节的 SHA-256，**不是音频摘要**。因此当前实现不保证两次播放得到相同的 WAV、波形、韵律或音色，也不证明受试者实际听见了任何声音——设备提交的 `tts_ended`/`media_ended` 只是媒体播放回执。若研究口径要求源播与重播在音频层面同一，需要另行设计持久化 audio artifact、SHA-256 绑定与原字节重放，那是独立工作，不在当前实现范围内。

平台已按受试者保存云处理 provider、告知版本、明确允许/撤销状态，并在每次云 ASR/LLM 外呼前重读；缺失、不匹配或已撤销都 fail-closed。这只是技术门禁，仍不得在伦理批件、知情同意/代理同意、供应商数据处理条款和院方安全评估明确覆盖上述三类外发数据前处理正式受试者数据。

## 双真相：自动训练与研究真值分层

- **AI 实时运营决策**：ASR/规则或 LLM 判类可驱动固定反馈、分级提示和流程推进，目标是减少研究者逐题操作。它可以失败、降级或被人工接管，不等于正式研究评分。
- **人工异步研究真值**：`confirmed_response_text` 与 ASR 原文分字段保存；研究数据仍以研究者复核并锁定的分数为准。AI 初评不得覆盖已锁定分，也不得把画像用于差异化判分。

在全协议就绪的 P0a 测试切片中，只有得到成功反馈或最终告知答案的 terminal attempt 才会在同一事务中自动物化为 `ItemEvent` 和未锁定的 `TurnEvent`；中间提示尝试只留在追加式证据账本。自动物化严格绑定冻结题位、source attempt、原始录音、服务端采集收据、checksum、字节数和数据分类，且保持 `confirmed_response_text=null`、`score_locked=false`。完整范围最后一条 TTS ACK 到达后，服务端重新独立评估证据；证据齐全才在同一事务生成不可变运行汇总并进入 `intervention_completed`，不齐全则进入可诊断失败状态，不伪造完成。

人工研究真值只能在 `intervention_completed` 复核窗写入：具名研究者先用 CAS 与稳定幂等键确认回答，服务端在无原文的追加式修订账本中保存前后摘要和操作者；然后只有在原始录音字节与上传收据一致时才能锁分。现场 closeout 是独立的 CAS/幂等记录；最终 `completed` 要求所有计划环节的研究真值已锁定且 closeout 已保存，完成时同时锁定 closeout。

## 通用题型合同与 AI 质量后台

本仓库已加入可表达单图命名、双图命名、开放回答和多场景的严格执行合同。只有经过执行准入并封存身份的合同，才能继续准入服务端观察；题库位置、协议批准、ASR/判定/提示/VAD 版本、规范化证据及其摘要、录音/转写/匹配器收据和 0→1→2→3 提示账本都会被绑定。静音不得伪造 ASR 或匹配结论；已知低于冻结阈值的结果必须进入低置信度安全分支；“部分正确”不能覆盖已经满足完整接受阈值的证据，显式部分表达式也必须绑定冻结表达式摘要。未分类、模棱两可、低置信度、ASR 失败和技术失败都是非计分安全分支，不得偷换成受试者答错。它目前仍是纯合同与转移内核，**尚未接入现有 autopilot 的持久化服务端证据账本、会话 CAS、运行修订与幂等指令收据**，也不支持任意临床流程图；不能表达的批准方案必须拒绝运行，不能在执行层偷补默认规则。

`分析后台` 会请求具名账号权限内的 `/quality/ai-metrics`，且首版只返回真实研究或模拟分区的一条 overall 聚合。researcher 只聚合本人场次，data steward 只聚合已进入终态的场次，admin 聚合全部授权场次；不同权限范围的数字不能横向比较。模拟分区可显示隐私状态、证据覆盖、固定排除原因和 AI 运行质量，不返回受试者、场次、题目、录音、转写或自由文本版本维度。统计只信任服务端追加式收据；`prompt_level=3` 当前只能证明录音尝试发生在第 3 层上下文，尚无床旁“答案已实际呈现”收据，因此告知答案次数/比例保持未知。延迟仅表示“录音上传完成→判类完成”，不得表述为完整交互时延。服务端在模拟分区第一条查询前建立 PostgreSQL `REPEATABLE READ + READ ONLY` 或 SQLite 显式 `BEGIN` 快照，在同一快照中完成权限投影、固定行数/文本字节/声明音频预算与九类证据加载，加载后还会对实际对象重算一次总预算。完整输入与数据库会话解绑并结束只读事务后，才会扫描/流式哈希音频，避免质量页长时间阻塞床旁写入；每个请求只扫描一次音频目录。模拟查询还有独立突发/补充限速，所有成功与可预期错误响应均明确不可共享缓存；即使反向代理返回非 JSON 429，前端也会保留合法 `Retry-After` 并显示冷却倒计时。真实研究分区必须经过双人两阶段切纪元：同一稳定事务重算聚合、九类证据水位与三张去标识行快照，提案摘要还绑定截止时刻、五项冻结政策、密钥编号与构建人；总人数不足直接拒绝，每个指标再按真正进入其分母的受试者数独立抑制。批准后研究聚合与 `/research/v1/*` 只复读不可变纪元，旧纪元没有行快照或快照损坏时返回稳定 503，绝不回退活读。这个看板是内部质量监测，不是正式研究结论；已有永久 scale harness 用 240 个重复合法 Week 2 场次跑通 15.84 万条证据的机械容量链，但完整 8 周内容仍是独立未完成验收。

## 正式受试者启用门禁

以下条件未全部留证通过时，平台保持“仅模拟/技术验证”：

1. **伦理与云处理**：批件、同意书/代理同意、声纹与回答文本处理说明明确覆盖 TTS/ASR/LLM 数据流、供应商、区域、留存、撤回和删除。
2. **临床内容**：当前 60 个 Week 2 交付缺口（70-position 运行计划内 50 个 + 未结构化多要素源位置 10 个）全部闭合，目标周题库、图片、提示、可接受答案和双/多要素评分口径完成临床双人核对，并同时达到 `frozen`、`operational_autopilot_ready=true` 和 `ready_for_research=true`；两类正式结局工具的具体名称、版本、授权、条目和计分算法由 PI/临床团队冻结。
3. **正式自动化范围**：实现并审核正式研究级 autopilot scope；当前 P0a 仅限模拟，禁止以移除 simulation guard 的方式放行。
4. **正式量表结果与流程**：在已实现的通用正式评估合同上，安装并验收真实冻结定义/计分制品、逐题录音服务端收据与不可复用绑定，以及排期/分配/延期/收尾/切换政策的可信执行适配器；definitions 冻结不能替代这些运行时证据。
5. **研究数据**：每次录音、转写、AI 判断、提示、人工接管和最终锁分可追溯；AI 与人工一致性达到课题组预设阈值。
6. **真机可靠性**：目标电脑/平板、真实网络和麦克风完成长回答、沉默、噪声、断网、刷新、暂停恢复、云超时和人工接管测试；自然度与识别率由目标人群样本验证。
7. **安全与运维**：账号、TLS、最小权限、Key 轮换、备份恢复、撤回隔离、去标识导出和音频删除闸门演练通过。

虚构档案、临时账号、床旁 PIN、已审核 20 题安排和离线语音就绪证据，服务

`--browser-check start-pause` 在同一个一次性环境里用**真 Chrome** 跑一遍
「开始练习 → 暂停」，再用仓库 venv 读临时库账本，把浏览器观察到的
command_key / session_id / revision 与服务端持久化事实逐项对上；收据写成
0600 文件，拒绝覆盖、拒绝符号链接、拒绝错误属主。这条路径**只在这台
macOS 开发机上成立**：它要求本机已装 Python Playwright（见
`requirements-dev.txt`）和 Google Chrome，两者缺一即明确停止，**不会自动
联网安装**；`playwright` 故意不进 `requirements-deploy.lock.txt`，所以
**CI 永远覆盖不到这条路径**，它绿不代表 CI 验过，也不代表真实设备验收
通过（真机验收另见 `docs/acceptance/` 下的八项清单）。

容器发布只安装 `requirements-deploy.lock.txt` 中逐包哈希锁定的 Python 3.12 传递依赖；`requirements-deploy.txt` 只是人工维护的直接依赖输入。更新依赖时必须重新生成 lock、复核差异并跑完整回归，不能在发布机临时 `pip install`。默认发布锁不含可选 Piper；若挂载本地 Piper 模型，镜像中必须同时安装与验证固定版本的 `piper-tts`，否则保持模型与包同时缺失并走明确降级。

许可边界与运行边界同样必须锁死：当前本地审计到的 `piper-tts 1.4.2` 包元数据标记为 `GPL-3.0-or-later`，各音色模型还可能有独立许可。任何对外交付的镜像/安装包若包含 Piper 或音色模型，必须先留存依赖和模型来源、版本、许可文本、使用/再分发权证据，并由负责人审核适用的 GPL 交付义务。未完成时继续使用不含 Piper/模型的默认发布，不得宣称本地 Piper 已交付。

- 启动自动 `alembic upgrade head`(幂等);schema 变更一律走 `alembic revision --autogenerate`,**真机严禁删库重建**。
- 内网模式在监听 `0.0.0.0` 前会执行 `check-ready`：未显式给 PIN 时先安全生成 8 位数字；缺研究者账号或显式配置了弱/非法 PIN 则直接退出，不会启动一个 console 全 401 的半成品环境。
- 内网模式必须 https:平板浏览器麦克风(getUserMedia)仅在 secure context 开放。证书/私钥在 `data/certs/`(gitignored),不外发。
- 换 PostgreSQL:设置 `DATABASE_URL=postgresql+psycopg://...`，再执行 `alembic upgrade head`；应用与 Alembic 共用该变量，不要直接改源码默认值。
- **语音 SOP**:老人端页面打开后先点"点一下,开始"覆层(浏览器要求用户激活后才放行朗读;刷新后需再点一次)。**此后两条路径分开看**——*旧手动/legacy*:仍需人点开始/结束,单段 5 分钟安全上限,录音前等小语把问句读完;*exact/autopilot*:当前 exact TTS 音频真正播完、设备提交 `tts_ended`、服务端已签发当前 record 命令后,前端自动开麦,不需要第二次点"开始回答",也没有旧的 900 ms 固定等待。浏览器权限、同意/资格/录音允许、场次分类、capability 与当前命令等门禁仍可阻断并安全暂停;暂停/断线/刷新后**不会凭浏览器缓存、旧的、已消费的或已失效的状态自行重开麦克风**——但也**不要求服务端一定重发一条新命令**:仍处于 pending 的当前 exact record 命令,在重新激活并重新验权仍然有效时,可以安全继续并自动请求麦克风;没有有效的当前命令就停下,不能凭浏览器缓存补造记录。配置云 Key 时后端可能先调用云 TTS 并缓存合成音频；**下面这条只适用于 generic/manual**:不希望任何话术出网时，显式使用本地 Piper/关闭云引擎，并在目标设备验证系统语音是否真正离线;exact/autopilot 不能这样切本地兜底,满足不了 Qwen-only 就是明确失败/暂停(见"音色链路")。
- **录音时长口径**:当前 exact/autopilot 的**录音停止路径没有实时声学 VAD,也不会用 VAD 决定何时停止**(这不否定严格执行合同里的 VAD 版本字段、ASR 之后的沉默判定,也不预判未来协议)。协议层服务端硬上限 15 秒,前端约 14 秒主动结束;这 1 秒是 `CAPTURE_STOP_JITTER_TOLERANCE_MS`,**只覆盖定时器迟到与 `Recorder.stop()`/媒体事件派发的抖动**,不是给上传或网络往返用的——上传发生在物理停麦之后,不占这 1 秒。取得麦克风权限及权限返回后的第二次服务端授权都在 `MediaRecorder.start()` 之前完成,共用独立的开录前预算,不占老人的 14 秒作答窗口;作答窗口从真实 `onstart` 起算。`stop_reason=max_duration` 只说明计时到限,**不**说明系统检测到沉默、判断患者说完或认为回答完整。老人端保留"说完了可以点这里"的可选提前结束按钮;停止后到收据/ACK 闭合之前,老人端显示"已收音，正在保存，请稍候"并隐藏主开始/结束按钮——这一条只有实现与自动 render 测试证据,尚无现场 transient 截图,不算目视验收。`audioSaved` 只代表音频已保存,业务推进仍以服务端完整 terminal evidence/receipt/ACK 为准。
- **旧手动/legacy 的两种录音驱动**(鼠标/触屏都行;**本条不适用于 exact/autopilot** —— 那条路径的自动开麦与约 14 秒自动结束以上面"语音 SOP"和"录音时长口径"两条为准):①老人自助——老人端点"点这里,开始回答"开录,点"我说好了"结束;`audioSaved` 只代表音频已保存,不会直接跳环节,推进依赖服务端独立证据链与 terminal receipt(服务端托管观察台为本地实现,不代表 T5 真实供应商与浏览器金链已验证);②研究者驱动——操作端"示意老人录音"/停止。录音只在同意、普通话资格、录音允许和场次分类均明确通过时开放，“未评”也会 fail-closed。单段录音有 5 分钟安全上限；任何麦克风、上传、ASR 或判定不确定性都必须安全暂停，不得消耗提示层级。
- **双端与暂停 SOP**:研究者端场次栏显示老人端在线状态、当前屏幕和最后心跳；超过 15 秒无心跳按离线处理。暂停会立即关闭老人端朗读与麦克风并保留当前场次位置，继续时只恢复安全游标，**不会凭浏览器缓存、旧的、已消费的或已失效的状态自行重开麦克风**；断线重连也不要求服务端一定重发新命令——仍 pending 的当前 exact record 命令，在重新激活并重新验权仍有效时可以安全继续并自动开麦；没有有效的当前命令就停下，不补造记录。
- **受控模拟自动流程**：只有同时设置 `ALLOW_SIMULATION_DATA=1` 和 `ENABLE_AUTOPILOT_P0A_SIMULATION=1` 才会开放 P0a 模拟入口；本机可直接用 `DEMO20=1 ./scripts/serve.sh`。它仍只接受服务器证明的 simulation subject/session，并继续执行 VisitPlan、provider readiness 和设备 capability 门禁。精确绑定的 `week2-single20-demo-v1` 可运行 20 题合成模拟计划；默认 canonical 整计划仍因 60 个交付缺口 fail-closed，不能用该开关启用真人或正式研究。
- **音色链路(两条路径规则不同,不可互相套用)**:
  - *generic/manual TTS*(旧 `/tts/speak`):有 Key 且 `TTS_ENGINE=auto` 时优先百炼 Qwen TTS，固定白名单话术会离开服务器并按引擎/参数/文本缓存；云失败后回退本地 Piper，再回退浏览器系统语音。浏览器系统语音是否联网取决于操作系统与语音包，不能一概视为离线。需要纯本地验证时显式设置本地引擎并断网实测。
  - *exact/autopilot TTS*(服务端签发的当前命令):**只能是 Qwen**。缺 Key、云调用失败、返回的不是这条流式路径认可的 exact WAV、或任何一项严格校验不过,都明确失败/暂停并如实记账,**绝不**回退 Piper,也绝不回退浏览器系统语音。generic 的降级规则不适用于这条路径。

## 不可触碰的硬约束(提测逐条对)

1. **★画像不进判分**:画像只喂交互,绝不进判分与评分口径。结构(JudgeInput 无画像字段)+运行时守卫+API 边界 400+前端 oxlint 导入守卫,四层设防;`Week1Profile` 独立成表、判分侧不得 join。
2. **音频删除闸门**:完整场次导出成功+受控副本真校验通过(信度样本还需人工复核)才可能删除；禁止逐条盲翻状态和无条件到期删除。物理删除默认关闭，仅受控环境显式设置 `ENABLE_AUDIO_DELETE=1` 后仍需全部闸门放行。
3. **去标识导出**:受试者/场次/音频/历史批次分域使用版本化 HMAC-SHA256 token；未配置独立的≥32-byte `DEIDENTIFICATION_KEY` 与非机密 Key ID 时拒绝导出。默认包不信任客户端 PHI 标记，转写/人工确认/AI 理由/现场备注及精确绝对时间全部移除，仅保留序号、时长等相对证据。每次导出意图还必须携带高熵幂等键；服务端只保存其摘要，以 `ExportBatch`/`ExportArtifact`、安全相对路径、SHA-256 与原子 manifest 形成可恢复发布账本。写文件前必须持有数据库 staging 租约和磁盘所有权凭证；崩溃后只有租约过期且凭证与上一 owner 匹配才能清理重建。claim、manifest 意图和最终发布都会按同一行锁顺序重验当前撤回/同意/二次使用/音频隔离状态。已发布批次在后续撤回后会立即禁止读取和 checksum 推进，但不自动物理删除不可变账本/文件；撤回、销毁和已交付副本追踪必须按 PI 批准的 SOP 执行。零新增录音仍会发布完整 CSV+manifest 批次，同一场次不能并发形成两个权威批次。
   `controlled-audio-exports` 里的原声副本即使使用 HMAC 文件名，仍含声纹和口语内容，**始终不属于去标识包**，必须与 CSV 分目录按原始敏感数据管理。
4. **双真相**:AI 判类只负责实时流程与初评；研究真值以人工复核锁定分为准，AI 永不覆盖锁定分。
5. **云数据透明**:TTS 只发白名单固定文本；ASR 会发原始回答音频；LLM 会发题面判分上下文和回答文本。不得把“自有服务器落盘”表述成“所有数据不上云”。
6. **fail-closed / fail-degraded**:内容未冻结、认证配置不完整、TTS 文本越过白名单时明确阻断；云引擎缺失或失败时明确降级本地/人工，不得伪装成成功。
7. **正式研究门禁**:伦理、临床内容、真实设备、数据追溯和运维演练未留证通过前，只能模拟预演和技术验证。

## 技术栈
