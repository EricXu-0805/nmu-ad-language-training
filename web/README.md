# platform/web

南医大语言沟通训练系统的双端 React 前端：

- `/console`：研究员/护理员操作端；
- `/patient`：老人端，仅显示大图、固定话术与录音控件，不显示 ASR/AI 判定。

双端运行时由服务端保存当前场次的任务/关系建立游标和暂停状态，命令序号也只由服务端签发。老人端先用当面 PIN 换取短时、绑定单场次的设备 capability，之后每 5 秒发送不含研究内容的最小心跳；研究者端使用具名账号读取在线状态、当前屏幕和录音回报。暂停或断线会关闭老人端麦克风和朗读。继续或重连**不会凭浏览器缓存、旧的、已消费的或已失效的状态自行重开麦克风**；但这**不要求服务端一定重发一条新命令**：仍处于 pending 的当前 exact record 命令，在重新激活并重新验权仍然有效、且属于当前场次与当前设备 capability 时，可以安全继续并自动请求麦克风。没有有效的当前命令就停下，不凭缓存补造。

当前仅用于本地开发和模拟预演。能通过 VisitPlan 审批/开场合同的仅是第 2 周正式训练模拟安排；真实研究因 `ready_for_research=false` 被阻断。第 2 周源脚本实际有 80 个位置：当前 70-position 运行计划内仍有 50 个自动协议缺口，另有 10 个多要素源位置尚未结构化，因此总交付缺口为 60。前端不得显示为 AI 已就绪，服务端也会在接管前拒绝启动。第 1 周及第 3–8 周尚无可独立完成的运行合同。

## 本地开发

先在 `platform/` 启动后端：

```bash
./scripts/serve.sh
```

需要前端热更新时另开终端：

```bash
cd web
npm ci
npm run dev
```

Vite 会把 API 请求代理到本机后端。医院内网双设备模式请从 `platform/` 使用 `INTRANET=1 ./scripts/serve.sh`，不要单独暴露 Vite 开发服务器。

## 提交前验证

```bash
npm run lint
npm run build
```

构建产物写入 `web/dist/`，由 FastAPI 同源托管。运行期不依赖 Node.js。

## 数据与隐私边界

- 浏览器只请求同源后端，不直接持有云 Key；后端可按配置调用云 TTS、ASR 和 LLM。云 ASR 会处理回答音频，云 LLM 会处理回答文本，完整边界以根 `README.md` 和 `DEPLOY.md` 为准。
- 前端不得自行增加外部字体、CDN、遥测或绕过后端守卫直连第三方模型。
- 浏览器 IndexedDB/localStorage 只作设备侧暂存或缓存，不能作为研究事件的唯一事实源。
- 录音必须校验服务端回执的音频 ID、字节数和 SHA-256，再确认源设备 IndexedDB 副本已清理，才可发出“已保存”并推进环节。
- 跨刷新音频 outbox、服务端 checksum/字节数收据和终态处置标记已接入。旧版遗留缓存只在服务端能证明同 ID 完整性时自动清理；404、未上传、无 checksum 或归属不一致的孤儿继续保留/隔离。任何收尾电脑的本地删除都不能冒充另一台平板已清理的证据。
- 真实研究只有 `recording_allowed=true` 且其余准入条件明确满足时才可启动录音；空值不是允许。模拟场次必须由服务端显式标记并由部署环境单独开启。
- **两条录音路径不是同一套规则，别混着读**：
  - *旧手动/legacy 路径*：仍然由用户或研究者点“开始/结束”，单段有 5 分钟安全上限。
  - *exact/autopilot 路径*：页面首次进入或刷新后仍需一次“点一下，开始”做浏览器激活；此后，当前 exact TTS 音频真正 media ended、设备提交 `tts_ended`、且服务端已签发当前 record 命令时，前端**自动**请求麦克风，不再要求第二次点“开始回答”，开麦前也没有旧的 900 ms 固定等待（`AUTOPILOT_IDLE_TICK_MS` 仍在，但只是没有可执行媒体时的有界轮询节拍；`record_ready` + pending record 命令时该间隔为 0）。浏览器权限、同意/资格/录音允许、场次分类、capability 与当前命令等门禁仍可随时阻断并安全暂停。
- **exact/autopilot 的停止路径没有实时声学 VAD，也不会用 VAD 决定何时停止**（这不否定严格执行合同里的 VAD 版本字段、ASR 之后的沉默判定，也不预判未来协议）。协议层服务端录音硬上限 15 秒，前端约 14 秒主动结束；这 1 秒是 `CAPTURE_STOP_JITTER_TOLERANCE_MS`，**只覆盖定时器迟到与 `Recorder.stop()`/媒体事件派发的抖动**，不是给上传或网络往返用的——上传发生在物理停麦之后。取得麦克风权限及权限返回后的第二次服务端授权都发生在 `MediaRecorder.start()` 之前，共用独立的开录前预算；老人的约 14 秒作答窗口从真实 `onstart` 起算。`stop_reason=max_duration` 只表示计时到限，**不**表示检测到沉默、患者说完或回答完整。“说完了可以点这里”这个可选提前结束按钮保留。
- 停止之后、上传/收据/ACK 尚未闭合的那段时间，患者端显示“已收音，正在保存，请稍候”，主开始/结束按钮隐藏。这一条目前只有实现与自动 render 测试证据，本轮**没有**抓到该过渡态的现场截图，不得写成真人目视验收。`audioSaved` 也只代表音频已保存，不能单独代表业务完成；推进仍依赖服务端完整的 terminal evidence/receipt/ACK。
- 原始声纹不是“去标识数据”，必须与分析表分开治理。
- 前端只能把服务端明确声明的“完整计划可自动执行”视为自动驾驶就绪；未知、`draft` 或 `operational_autopilot_ready=false` 均关闭启动入口，服务端仍做最终重验。
- 前端只展示服务器签发的合成服务检查结果：具名管理员用固定白名单内容实际跑通 TTS→ASR，并检查已配置 LLM；检查缺失、过期、配置变化或必需能力失败时，自动干预入口保持关闭。环境中存在 Key 或单独听到 TTS 发声都不是“AI 自动化可用”的证据。
- P0a terminal attempt 自动生成的 Turn 只是运营证据投影，初始必须保持人工确认为空、研究分未锁；最终研究真值只能在床旁干预结束后由具名研究者确认和锁定。
- 不要清空 `platform/data/`、浏览器录音暂存或现有数据库来“修复”问题。

## 常见问题

- 麦克风不可用：单机使用 `localhost`；平板通过内网使用 HTTPS，并先信任本机自签证书。
- 两端不同步：先看研究者端的老人端在线状态、当前屏幕和最后心跳，再确认场次编号与 PIN；不要重复创建题目/环节。
- 刷新或换设备后续做：以后端 runtime 与 journal 恢复结果为准；系统只恢复已提交记录与安全游标，不凭浏览器缓存或已消费/失效的旧状态恢复录音。仍 pending 的当前 exact record 命令在重新激活并重新验权仍有效时可以安全继续；若服务端没有对应题目/环节或没有有效的当前命令，先停止，不要凭浏览器缓存补造研究记录。
- API 返回题库未冻结或周次不支持：这是安全门，不要在前端绕过。
