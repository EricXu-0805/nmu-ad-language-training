## 2. 本轮新增修复

### 2.1 反向代理请求体在进入应用前限流

- 只有规范的 `PUT /audio/<safe-id>/blob` 可到 64 MiB；其余路由在 Caddy 层限制为 256 KiB。
- 避免匿名登录、配对或普通 JSON 在认证限流命中前占用大块内存。
- 候选 `Caddyfile` 已通过当前 VPS 同一 Caddy 二进制的 stdin 只读校验；没有写配置、reload 或重启。

### 2.2 认证计算量和失败记忆有界

- 登录和床旁配对保留逐来源限流，并各自增加换 IP 也不能绕过的全局短锁。
- PBKDF2 在用户名查询前进入全局并发闸门；饱和时统一失败，不形成账号存在性 oracle。
- 失败/锁定键按时间清理，并用 LRU 硬上限防止唯一来源洪泛造成内存无界增长。

### 2.3 云 TTS 与缓存字节安全

- CosyVoice、Qwen base64、Qwen URL 和缓存统一执行 16 MiB 上限与 RIFF/WAVE 签名检查。
- base64 解码前后均限长并严格解码；缓存读取使用防软链接和普通文件校验。
- 损坏、超限或软链接缓存会被淘汰，不能永久命中或直接返回浏览器。

### 2.4 老人端 AI 探测请求风暴

- 未配对时不再请求 `/live/state`。
- 配对后只进行一次 AI capability 探测；精确的 `autopilot_not_active` / `autopilot_p0a_disabled` 成为当前场次稳定人工门禁。
- 408、429、5xx 和网络不确定性使用 1.5、3、6、12、15 秒有限退避，耗尽后显式锁定；终态停止探测。

### 2.5 代理来源信任 fail-closed

- 发现宿主 Caddy 覆盖文件过去只要求 `HOST_CADDY_BRIDGE_IP` 非空；误填 `*`、CIDR 或列表会扩大 Uvicorn 代理信任面，使客户端可伪造 X-Forwarded-For，绕过按 IP 认证限速并污染来源审计。
- 容器启动合同现在只接受一个 RFC1918 IPv4 或 ULA IPv6；拒绝空值、首尾空白、通配符、CIDR、列表、回环、未指定、多播、链路本地和公网地址。
- 失败只输出固定错误码，不回显输入。安全值和危险值均有回归；危险值在真实候选容器中以 exit 78 拒绝。
- Caddy 原生 `reverse_proxy` 已移除冗余的显式 XFF 覆写，保留其默认忽略客户端 XFF 的防伪行为；应用只信任精确 Caddy peer。

### 2.6 低内存 VPS 蓝绿边界

- 默认 Compose：app/migrate 为 512 MiB 内存、640 MiB 含 swap；Caddy 为 128/160 MiB。
- 宿主 Caddy 覆盖模式：候选 app 只发布到 `127.0.0.1`，为 384/512 MiB；Compose Caddy 默认不启动。
- 发布单元固定为不可变镜像 digest + 从已验证快照恢复的候选外部卷；旧镜像和旧卷必须成对保留、成对回退。

### 2.7 发布树卫生

- 23 个后缀为 PNG、实际为 JPEG 的审计截图改为 `.jpg`，引用同步更新；43 个审计图的后缀与 magic 均一致。
- `.DS_Store`、Ruff 缓存和浏览器临时制品已排除。
- 删除只有虚拟根包、未锁任何生产依赖的 150 字节 `uv.lock`；生产可复现依赖以 `requirements-deploy.lock.txt` 的完整 hash lock 为准。
- 用户提供的三个敏感凭据在候选集和完整 Git 历史均为 0 命中；它们只存在于被 Git/Docker 同时排除的本地 `data/` 中，目录/文件权限为 0700/0600。严禁 `git add -f`，异地副本仍须加密并设置硬配额。

## 5. VPS 只读预检结论

本轮只做读取和候选配置 stdin 校验，没有写远端文件、安装软件、升级、重启、reload、迁移或切流。

- 现网 NMU、宿主 Caddy、SSH 及同机其他既有服务当前健康；既有非本项目端口不得触碰。
- VPS 为 1 GiB 内存规格，可用资源有限；当前没有 Docker。首次启动 Docker 会改变 `ip_forward` 和 iptables，不能与应用迁移同窗。
- 系统有大量待更新包且需要未来重启；`/boot` 空间也需在维护窗前单独核对。系统升级、Docker 安装、应用迁移必须拆成独立可回退窗口。
- 当前快照可以通过 SQLite integrity、FK 和 manifest 只读核验，但历史备份脚本曾直接复制 live SQLite；本机异地拉取又未形成独立加密、硬配额、稳定调度的恢复证据，因此备份流程仍为 NO-GO。
- 推荐路径保持为：旧服务 `127.0.0.1:8000` 不动，候选 `127.0.0.1:18000` + 候选卷预演；验证后只 reload 宿主 Caddy upstream；失败立即 reload 回 8000，不 downgrade、不删卷。
