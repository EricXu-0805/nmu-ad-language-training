# 两张正式量表·定义采集单（交 PI / 临床冻结）

> **文件用途**：把两类"正式结局工具"从"只有类别"变成"可冻结、可校验、可运行"的定义。每张表填满并经 PI 签署冻结后，工程侧才可能把 `formal_result_contract_ready` 由 `false` 翻成 `true`。
> **依据来源**：`内容协议来源与PI冻结包_20260719.md` §7、§6；`安全审查_20260719.md` R-06 及 §8.1/§8.3、§9.3；`交付级回归记录_20260719.md` §10.3、§11.3、§12.1/§12.4。
> **生成日期**：2026-07-22　|　**本采集单版本**：v1（草稿，待 PI 填写）
> **红线**：本表只采集定义，工程不代填、不推断、不合并两个 Word/量表版本；任何空栏都必须由 PI / 临床内容负责人 / 量表授权负责人依权威原件填写。

---

## 0. 为什么这是硬阻断

1. 这两类是本研究的**主要疗效终点（primary outcome）**——论文结论、伦理承诺和统计分析都以量表分为准；平台当前**只有类别名，零条可运行工具定义**（无名称/版本/授权/条目/计分算法）。
2. 因此正式录入、自动计分和 `due → completed → approved-deferred → closeout → switch` 自动切换受试者**全部 fail-closed**；schema v4 在授权制品到位前对正式写入**永久关闭**，现有 `ScaleResult` 只是 `legacy_unverified` 隔离容器（`formal_outcome_eligible=false`）。
3. 这不是"在 JSON 里手写一个 `true` 就能绕过"——就绪标志由校验器按**内容寻址**从实际制品派生；没有 PI 冻结的授权/条目/计分制品，`formal_result_contract_ready` 与 `workflow_ready` 无法为真（详见审计 R-06）。
4. **训练表现绝不等于量表分**：训练正确率、AI 判分、提示等级、自由填写分在任何情况下都不能折算/估计为正式量表结果；"未训练词"命名测验的题目还必须与 Week 1–8 训练词表**可验证隔离**，否则终点被污染、研究失效。

---

## 1. 填写与冻结须知（两张表通用）

- **候选 ≠ 选定**：BNT / CERAD 中文命名任务是"量表一"的候选，CETI / CADL 是"量表二"的候选，均**尚未选定**；MMSE / MoCA 是基线认知严重程度**协变量**，**不是**这两张表。请在下方明确写出最终选定工具。
- **一张表 = 一个工具 = 一个版本**：改动任何一个字（条目、锚点、计分权重、施测语）即视为换版本、换 `definition digest`；不得原地改一个已开场会话依赖的定义。
- **可验证条目摘要**：条目/施测/计分冻结件须能算出**小写 SHA-256** 的 `definition digest`（工程会做内容寻址复核）。请随表附上冻结原件（PDF/表格/授权书），并在签署栏登记其 SHA-256。
- **标准测试向量必填**：计分算法必须附"输入 → 期望分"样例，用于验收自动计分引擎（见 J 栏）。
- **空栏语义**：留空 = 未冻结 = 该工具不可用；工程不会替 PI 猜测缺省值。
