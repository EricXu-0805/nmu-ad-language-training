## 2. 红线复核（三条硬红线 + 一条你必须知道的细节）

- **console/** 从不 import **patient/**：✅ PASS（双向 grep 均为空，两端只经 `sync/*` + 服务端通信）。
- **老人端永不显示错误/红**：✅ PASS。麦克风失败/取图失败/AI 不确定全部落到"我们先等一下 / 请研究者查看"这类**平静、非红、无 PII**的文案，技术故障**静默升级给操作端**（`isPatientRecFailure` 走控制台），不砸到老人脸上。
- **老人姓名/画像绝不进提示词或审计账本**：✅ PASS（`JudgeInput` 结构性排除画像字段 + import 期断言 + 账本 allowlist 只收标量元数据，没有 transcript 键）。
- ⚠️ **但"回答文本永不进提示词"不是字面成立的**：`_classify_operational` 会把老人 ASR 文本放进判分提示词，发给云端 LLM——**仅当**该受试者有逐人云处理授权(`cloud_llm_allowed`) **且** provider 声明 CLOUD 边界时才发；边界 UNKNOWN 直接 `raise`（fail-closed），无授权则退回本地规则，调试旁路 `/judge/classify` 强制本地。**真实不变量是"没有逐人云授权就不外发回答文本"，不是"永不外发"。** 这条影响伦理/数据治理话术，别对丁老师说成"回答完全不出网"。

## 3. Codex 干的活，分三堆看

### A. 真实有价值、值得要的（测试全绿 + 架构自洽）
- **老人安全内核**：麦克风/设备/权限失败**不再被当成"答错"**去升级线索、告知答案、自动跳题——这是最有价值的一个修复（污染干预+研究数据的老 bug）。
- **答案/图片不泄漏**：图片移到服务端私有目录、只发当前题、`blob:` URL、不给老人端任何 image_id/目标词；大小写静态回退泄答案包也堵了。
- **fail-closed 门禁**：录音同意、完成收口、撤回治理、导出/删除批次都收到服务端，前端按钮只是建议。
- **跨账号授权/存在性预言机**：object-authz-first + 统一 404，堵了一批 session_count/403-vs-404/跨 owner 侧信道。
- **备份完整性**：SQLite integrity_check + schema/DB↔audio 闭合，拒绝空壳/半截快照当"可恢复"。
- **生产机边界加固**（已上线）：答案路由 404、安全响应头、SSH 仅公钥、data 0700/DB 0600。

### B. 过度工程 / 有风险，**先别要或先隔离**
- **同名内核 = 10,872 行"惰性但缠绕"的代码**（⚠️ 比"死代码"更麻烦，见 §8 修正）：`task_adjudication_contract/ledger`、`task_contract_chain/ledger/runtime`、`task_execution_contract`、`task_response_fingerprint` 七件套。**主程序确实零调用、表永远是空的**（`main.py:2445`/`visit_plan_service.py:885` 只把 `task_contract_bundle_id` 写成 `None`），所以运行期完全惰性。**但它不是一个能一删了之的孤岛**——备份完整性校验器 `scripts/verify_backup_snapshot.py` 真的 import 并调用了它的 `verify_task_contract_archive`/`verify_task_adjudication_archive`，而且 `session`/`visit_plan` 两张**活表**带着指向它的 FK 列，那 2 条迁移（`a6c9d2e4f713`/`c4e7a1d9b206`）也是**混合迁移**（既建死表、又给活表加列加 FK）。**结论：清掉它是一次真·重构（碰备份完整性 + 核心 schema），不是一次 delete。**
- **正式量表只是"空壳"**：schema 建好了，但 `formal_result_contract_ready`/`workflow_ready` 永远 false，正式写入被锁死——因为两张量表的定义/授权/计分根本还没有。
- **Docker 蓝绿部署路线**：和线上**裸机 systemd+caddy**冲突（80 口还有 clash/nginx、24697 有 sing-box 绝不能动），而且 Compose 外部卷**没有验证过的备份路径**，裸机 rsync 发布路径还被 Codex 删了。1GiB 内存跑蓝绿也紧。
- **构建不可复现**：Codex 的镜像是在 **Node 25** 上 build 的（声明是 Node 22），它自己承认"这不是 Node 22 可复现证明"。

### C. 你必须知道的一个"静默改动"
Codex 把你和我一起设计的 **"建档 → 一键保存并直接开训"一条直线**，改成了 **"建档 → 保存并创建训练安排 → 审核 visit-plan → 床旁台消费已审核安排才能开训"** 的多步流程。它的理由是研究严谨（区分模拟/真实数据边界、开训前要有审核过的安排、不暴露 session id）。**这更"研究正确"，但和你当初要的"每来一个新患者就从建档直接做流程测试"不一样了。要不要接受这个改动，是你拍板的事。**
