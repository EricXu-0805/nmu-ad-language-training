> 这份表要在**目标设备、目标浏览器、真实房间、真实网络**上填，全程只用虚构受试者和合成语音。
> 任何一项不清楚，都按未通过处理；修复或补齐条件后**重新验收该项**，不得沿用旧结果。
>
> 权威来源：`docs/acceptance/2026-08-12/自动对话链路验收计划_非技术版_20260812.md`（第 1–8 项）；
> 第 9–13 项是 2026-10 补的现场项目（现在回答，2026-11-27 起改为核对按钮已去掉；提前回答检测、静音自动收麦、现场裁定、指定起点），口径以本表为准。
> 本机自动检查与合成证据**不能**代替这张表。

## 用 `/acceptance` 向导时

在要验的那台平板上做，**老人端开始练习之前**做。服务器目前不收这份记录，交回靠下载的文件。

1. 先跑 `/device-check`，再在同一台平板的浏览器里打开 `/acceptance`，只开一个标签页。页面顶部的
   「本份记录编号」就是这份记录的编号，文件名和纯文本里都带它的前 8 位。
2. 填表头九格。设备型号、资产编号、系统、浏览器、麦克风、扬声器都照实物人工填，页面不会替你填；
   验收人填工作人员真名。**表头和备注里都不写老人姓名或编号。**
3. 点「采集设备参数」。页面会短暂开两次麦克风读设置，状态栏麦克风指示会闪一下；不录音、
   不保存声音。第一次可能弹麦克风权限，点「允许」。老人端正在用麦克风时页面不开麦、只记其余
   参数，这时先暂停或结束老人端练习，再点「重新采集设备参数」。结果里的「提前回答检测条件」
   只看这台平板，服务器开关另算。浏览器可能记住这次「允许」：做第 5a 项（拒绝麦克风权限）前，
   先到浏览器的网站设置里把本站麦克风改回「询问」。
4. 逐项做、逐项勾，备注写看到的现象。中途刷新、误点返回、锁屏回来，填过的都还在。页面若提示
   「这台设备存不了草稿」（私隐模式、存储被禁或已满），就一次填完、立刻冻结保存。
5. 做完点「完成并冻结」，再点「保存记录文件」，文件名形如
   `真机验收-<设备型号>-<日期>-<编号前 8 位>.json`。iPad Safari 一般存进「文件」App 的「下载」，
   安卓 Chrome 一般存进「下载」；找不到就看浏览器自己的下载列表。点了没反应（在微信等 App 里
   打开网页时常见），就点「复制 JSON（下载不了时用）」整段贴进消息；复制也失败时页面会把内容
   摆出来，长按全选复制。
6. 把 JSON 文件原样发给负责人（微信文件或邮件附件），失败项的截图一起发。不改名、不打开改内容：
   同一个编号只认冻结时那一份字节。「复制纯文本」只给人读，不能代替 JSON。
7. 冻结后发现填错，点「发现填错：解冻修改」：内容保留、换一个新编号，新文件里写明它取代哪一份。
   新旧两份都交回，按取代关系认新的那份。
8. 换下一台平板或下一次验收，点「开始新记录」。确认后本机上这一份就清掉了，先确认文件已经交出去。

每场开训前只需留一份当天的设备回执（页面版本号、设备参数）时，步骤相同，只是不勾项：填表头、
采集设备参数、冻结、保存并交回。这份回执的结论会写「未完成」，它只说明那天用的是哪台平板、
哪个页面版本，不算验收。

## 十三项

### 1. 正常题目：声音真正结束后才开始录音，「正在听您说」只出现一次

- 观察：AI 读完问句后屏上才出现「正在听您说」，这一题只出现一次。开了提前回答检测的设备，播报中系统状态栏的麦克风指示会亮——那是本机在听有没有人开口，只做分析，属正常。
- 通过判据：朗读结束 → 才出现「正在听您说」，「正在听您说」只出现一次；播报中系统麦克风指示可以亮，但不保存声音（事后核对这一题只有一段录音，从朗读结束之后开始）。
- 结果：□ 通过 □ 未通过 备注：

### 2. 没有文字回答：一级提示 → 二级提示 → 告知答案，之后不再开第四次麦

- 做法：麦克风开着但不说话，连续三轮。
- 通过判据：三次之后系统告知答案并停止，**不再有第四次收音**。
- 结果：□ 通过 □ 未通过 备注：

### 3. "再说一遍"：同一轮第一次重播、第二次暂停

- 做法：在同一提示层级里说"没听清"两次。
- 通过判据：第一次重播刚才的问题或提示；第二次直接暂停。进入下一提示层级后重新按新一轮计算。
- 结果：□ 通过 □ 未通过 备注：

### 4. 提示后答对：反馈播完并经服务器确认，才进入下一题

- 做法：在一级或二级提示后说出目标词。
- 通过判据：先在**当前题的画面上**听到正确反馈，反馈播完之后才换下一题；不出现"看着橘子听到苹果"。
- 结果：□ 通过 □ 未通过 备注：

### 5. 各种失败：全部关麦并停住，绝不自行恢复

逐项做，每项单独记录：

| 场景 | 做法 | 通过判据 | 结果 |
| --- | --- | --- | --- |
| 拒绝麦克风权限 | 浏览器弹权限时点"拒绝" | 立刻停住并给出可读提示，不重试 | |
| 拔掉/禁用麦克风 | 收音中拔掉外接麦 | 立刻关麦并停住 | |
| 播放失败 | 静音设备或占用音频 | 停住并提示，不跳过题目 | |
| 上传失败 | 断网后说话 | 本机立即关麦并停止继续；能上报就由服务器暂停，不能确认就要求联系负责人 | |
| 断网 | 关 Wi-Fi | 同上，且**不会假装服务器已收到** | |

- 共同判据：以上任何一种都**不算老人答错**，也**不消耗提示次数**。

- 通过判据：全局只有一个声音在放、一个麦克风在用；服务器回执没有重复条目。
- 结果：□ 通过 □ 未通过 备注：

### 7. 暂停 / 切后台 / 刷新 / 断网：立即物理关麦，恢复后不自行开麦

- 通过判据：每一种都**立刻**关麦；恢复后**不会凭旧状态自己重新开麦**。

### 10. 停播误停与漏停

先看播报时屏上写的是「想回答时可以开口」（这台设备在检测有没有人开口）还是「请听完再回答」（没在检测）。没在检测时只记下这一点，10b 照做。

| 场景 | 做法 | 通过判据 | 结果 |
| --- | --- | --- | --- |
| 漏停：播报中老人直接开口 | AI 读问句时老人直接说出答案 | 在检测时朗读停住，屏上提示看到「正在听您说」后从头回答；老人完整重说一遍，整句都在录音里。记下开口后朗读多久才停、有没有说了却没停 | |
| 误停：只有外放声音或旁人说话 | 播报中老人不说话；分别把平板音量调大、请旁边的人小声说话 | 朗读不应停下；停了就记下当时的声音来源。外放回声停下后只接着放同一句，不会多开一次录音 | |

### 11. 找词停顿不被静音收麦截断

- 做法：回答时先说一两个字，停 3–4 秒想词，再说完整答案（例如「这个……（停 4 秒）……是锚」）。另做一次：被提前回答检测停播之后重说，重说前也停一下。
- 通过判据：停顿期间不收麦，整句答案都在录音里；说完之后才收麦（自动收麦约等 3 秒；服务器关了静音收麦时只在点「说完了可以点这里」或作答时间到点时收）。停播之后那次重说只靠按钮或作答时间收麦。记下停了多久、有没有被提前收麦。
- 结果：□ 通过 □ 未通过 备注：

### 12. 老人已答对 / 跳过本题

让 AI 在一题中途安全暂停（老人端点「暂停练习」），研究者在训练台操作：

| 场景 | 做法 | 通过判据 | 结果 |
| --- | --- | --- | --- |
| 老人已答对 | 点「老人已答对」，选原因，可写备注 | 确认框写清第几题、第几环节；保存后 AI 从下一个环节或下一题继续；AI 自己的判定原样保留，裁定连同账号名和原因一起记录 | |
| 跳过本题 | 点「跳过本题」，选原因 | 本题剩下的环节记为跳过，不凭空生成回答或录音；AI 从下一题继续；导出里这一题的题号与跳过原因对得上 | |

### 13. 指定起点（含中止后同周第二场从第 N 题开始）

| 场景 | 做法 | 通过判据 | 结果 |
| --- | --- | --- | --- |
| 新场次从第 N 题开始 | 训练台「本场从哪一题开始」选第 N 题，填「跳过前面题目的原因」，点「确认从第 N 题开始」 | AI 从第 N 题开始；前面的题只留跳过记录，不生成回答或录音；屏上题号与导出里的总题号一一对应 | |
| 中止后同周第二场从第 N 题开始 | 把一场中止，同一周再开第二场，从上一场停下的第 N 题开始 | 第二场能从第 N 题开始，不被第一场的记录卡住；两场的录音、题号与导出各自对得上，没有重复计分 | |
