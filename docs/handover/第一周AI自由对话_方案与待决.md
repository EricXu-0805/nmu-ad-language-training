# 第 1 周「AI 自由对话」——现在做到哪一步，再往前要拍什么板

写给钱凯、丁老师与伦理审查。2026-08-30 起草，工程侧现状与三个选项的代价都写在这里。

---

## 一、钱凯 2026-08-30 提的问题，答案是「对，而且原因很具体」

第 1 周关系建立跟第 2–8 周走的是两条完全不同的链。

- 第 2–8 周有「自动带练」：题库 + 交互协议数据包，机器人自己问、自己听、自己判、自己给反馈。
- 第 1 周只有一份 `week1_script.json`，是研究者手动一问一问推的脚本，**不判分、不计分**。

冻结脚本里其实给每一问都写了「老人答完该说的那句」（`success` 字段，比如「好的，认识您真开心。」）。但那句从来没到过老人端——它印在研究者屏上，前缀写着「回答后说：」，**设计上就是让研究者本人开口念的**。所以老人答完，平板上还停在上一个问题，一个字也不响。

## 二、这一轮做了什么（已实现）

**一问拆两拍**：问句 → 老人回答 → 研究者点一下 → 机器人开口。说出来的话由同一把云端嗓子读，跟问句是同一个声音。

**开放式回应库**：28 句，分 7 组。研究者点的是「刚才是哪种情况」：

| 组 | 什么时候点 | 句数 |
| --- | --- | --- |
| 接着聊 | 老人说了具体的事，想让他往下讲 | 5 |
| 请他多说 | 老人只说了两三个字 | 3 |
| 肯定一下 | 说完了，暖一句就够，不再追问 | 9 |
| 想不起来 | 老人说不知道、忘了 | 3 |
| 陪一下 | 老人语气低落或说得着急 | 3 |
| 没听清 | 没录清楚，或老人没开口 | 2 |
| 拿不准 | 不确定归哪一类 | 3 |

同一组连点两次不会说同一句（组内轮换）。9 句是追问型（会把话头递回给老人），其余只肯定不追问。

**开放选句用在这七问**：自我介绍的属相、兴趣、日常活动，以及介绍机构环境的四问（2026-09-04 Eric 拍板把属相也放进来）。**姓名、年龄那两问永远不走这条路**——回答是直接身份信息。

## 三、为什么是研究者点，不是 AI 自己判断

原打算让 LLM 读老人这句话的转写文本，再从库里挑最贴的一句。**查代码后这条路今天走不通**：

- 转写绑在「场次 attempt / capture-lease 证据链」上，需要题库、题位、评分行。
- 第 1 周不判分、没有 attempt、没有题库，**录音本来就不转写**。
- 旧的 `POST /asr/transcribe/{id}` 单点接口写着「已永久关闭；请使用场次 attempt/process 权威证据链」。

所以系统这一侧**根本没有「老人刚才说了什么」的文本**。要有，得为第 1 周单建一条转写通路，那是一个新的出网面加一份新的证据义务，不是加个函数。

而研究者就坐在旁边、刚听完那句话。**他的判断比任何自动分类都准**，而且零延迟、零新增出网。所以这一版把这个判断交给人。

## 四、往前走的三个选项，代价不一样

### 选项 A（已实现，今天就能用）
研究者点分组，系统在组内轮换。机器人说出口的每个字都是事先定稿的。
- 红线：不动。伦理：不用重过。成本：只等钱凯把这 28 句签了。

### 选项 B：LLM 从同一个库里挑句
要先建第 1 周转写通路：老人录音 → 云 ASR → 文本 → LLM 选 id → 说库里那句。
- **机器人说出口的字仍然全部是签过的**，白名单一个字不用改。
- 新增的是「老人第 1 周的语音和转写文本出网」。第 1 周自我介绍段含姓名年龄，
  即使把那两问排除在选句之外，**同一段录音里仍可能带出身份信息**——这一条要伦理明确。
- 延迟：ASR 约 2–4 秒 + LLM 约 1–2 秒。老人答完到机器人开口大约 5 秒。
- 还要决定：转写文本存不存、存多久、进不进研究导出。

### 选项 C：LLM 现编回应
不再从库里挑，直接生成。
- **必须开云 TTS 白名单**：从「冻结闭集」放宽到「闭集 ∪ 本场老人自己 ASR 文本的模板注入」。
  这是这个平台迄今最大的一次数据边界变更。
- 还要新加输出闸：禁标识、限长、限轮次、禁承诺、禁纠正老人记忆。
- 机器人会对痴呆老人说出**没有任何人事先看过**的句子。这一条本身就是伦理审查的对象。
- 工程侧不难；难的是谁为那句话负责。

**建议先跑 A，用真实场次攒够素材再判断 B 值不值。** 如果 A 跑下来研究者觉得七个分组够用，B 的收益主要是省研究者一次点击，不足以换那条出网面。

## 五、要钱凯拍的四件事

1. **那 28 句签不签**。现在文件里写着 `qc_status: draft`、`signed_by: null`，工程侧照签字工件判定就绪，不改代码。要改词、要加句、要删句，都是改这一个 JSON 文件。
2. **追问型要不要留**。9 句会把话头递回老人（「您再多讲一点吧」）。这会拉长第 1 周那 20 分钟，也可能正是想要的。要关掉就把 `invites_more` 那几条删了。
3. **机器人说了哪一句要不要记进研究记录**。⚠️ **这条现在是缺的**：以前第 1 周全按固定脚本走，事后照脚本就能还原机器人说过什么；现在回应变成可选的，**不记就还原不了**。工程侧记一条不难，但「记什么、进不进导出」是研究口径。
4. **介绍机构环境那四问**，冻结脚本原本一句回应都没写。现在由回应库接管。如果想给这四问写专属回应句，也是改同一个 JSON。

## 六、和这件事一起改的：语速

原来云 TTS 是 0.9 倍速（为老人听清而放慢）。**把一把正常语速的合成嗓子拉慢，韵律会一起被拉长，人耳对这种「匀速的慢」特别敏感——这本身就是机器感的来源。** 2026-08-30 耳测对比后改回 1.0。

代价是缓存键带语速，1264 句预合成全部作废重跑了一遍。要改回去或者换音色，都是改生产 `.env` 一行加重跑一次预合成，不动代码。**音色还有 10 个候选没定**，CosyVoice 那边有几把明显更生活化、不像播音腔的（龙老姨、龙应聆），钱凯要是对嗓子有意见，可以听过再定。

## 七、2026-08-31 追加：Eric 拍板直接做互动态，已实现

Eric 2026-08-31 的决定：「最后还是要做成互动的状态……按照 LLM 自动去给回复，
然后语音也记下来。」即选项 C 的受控落地。当天完成，与迁移 `d0c22a6dae2a`
一起上线（2026-08-31 窗口，收据 236 §七）。语速同日先回 0.9，后 Eric 拍板终态 = 1.0（两套缓存都留盘，可即切）。

### 现在的动线（老人视角）

老人答完 → 录音落账 → 系统把这段录音送云端转写 → qwen-plus 听完**现编一句**
口语化回应 → 机器人用同一把嗓子说出来。研究者不再需要点分组；屏上开关
「老人说完自动回应」默认开，随时可关回手点。

**问级绑定（2026-09-04 起，取代此前的节级限制）**：录音在设备开麦那一刻锁存
「关系建立·<节>#<问>」，服务端只对录音自己的问位放行自动回应——姓名/年龄两问的
录音永远进不了云，属相/兴趣/活动三问与机构环境四问走完整的转写→现编链。此前
「自我介绍节整节不开自动回应」的口径作废；伦理报备按七问进云、两问不进云的口径写。

### 四级降级梯（每级都落回签过流程的冻结句库，老人永远有回应）

| 情况 | 机器人说的 | 记录里的原因 |
| --- | --- | --- |
| 录音听不清 / 转写技术失败（本问**第一次**） | j1「没听太清楚，您再说一次好吗？」 | asr_failed |
| 录音听不清（本问**再次**，或已是末轮） | j2「没关系，那我们聊点别的吧。」 | asr_failed |
| 老人没说话 | j2「没关系，那我们聊点别的吧。」 | asr_empty |
| LLM 不可用 / 生成越界被拒 | k1「好的，谢谢您告诉我。」 | llm_unavailable |
| 受试者未授权云处理 | k1 同上（**一个字节不出网**） | cloud_not_authorized |
| 本问已聊满设定轮数 | k1 同上（**不调云**，属正常收束不计入降级率） | round_limit |

同一个 `asr_failed` 对应两句不同的话是有意的：**同一问只请老人重说一次**，再听不清
（多为网络/ASR 故障，不是老人的错）就收束，不反复要求痴呆老人重复自己。

### 红线的一次显式放宽（要伦理与钱凯知情）

- LLM 现编句不在云 TTS 冻结白名单里。发声走新的「按持久行合成」设备端点：
  文本只能按编号从只追加账本加载，客户端结构上递不进任何文本。
  出网授权依据 = 行已持久化 + 该受试者已过逐人云授权（llm 行只会为已授权
  受试者生成）。`/tts/speak` 那个接受客户端文本的口子一个字没放。
- 生成守卫：≤60 字、单句、禁问姓名/年龄/住址等身份信息、禁医疗建议、
  禁槽位符/控制符；越界即弃用、落句库。prompt 全文在 `app/rapport_reply.py`。
  **身份问询那条是子串黑名单（现 17 条）+ 一道按模式的兜底（年份/年纪/出生/
  贵庚/住址等，2026-09-05 加）**，兜常见问法但非穷尽——第一道约束是 prompt，
  两道守卫都是概率性兜底；伦理复核请按这个口径评估，不要当成硬保证。
  **属相一问只聊一轮**（Eric 2026-09-05 拍板，回应库 `applies_to` 里该问位
  `max_rounds: 1`）：老人答完属相，机器人只接一句、不追问、不再开麦——属相之后
  最顺口的追问就是「哪一年的」「高寿」，老人一答就是被排除在云外的出生年份/年龄。
  单轮之后这条路不存在了：属相那一问进云的只有老人答属相的那一段。兴趣/活动两问
  仍按全局上限（默认 2 轮）追问，两道身份守卫照旧兜着。
- **机器人会对痴呆老人说出没有任何人事先看过的句子**——三、四节写过的那句
  伦理判断没有变，现在它是一个已被接受的、需要伦理复核确认的现状。

### 决策点 3（记录）已关闭，新的记录事实

机器人在回应拍说的每一句——AI 现编、手点句库、脚本句、兜底——都落
`rapportutteranceevent` 只追加账本：说了什么、来源、哪段录音触发、降级原因、
引擎版本。**llm 行还保存了喂给生成器的老人转写文本（asr_text）**——这是患者
数据，不进任何研究导出/研究只读接口；研究者可在分析后台「第 1 周对话回放」
按场次读权限查看（与逐次作答 asr_text 同一暴露面），保留在库里供审计。

### 还要钱凯/丁老师拍的

1. 28 句回应库仍是 `qc_status: draft`——现在它是降级梯的兜底层，签署更必要了。
2. LLM 现编这件事本身 + 上面的生成守卫，要不要按伦理流程报备/复核。
3. `asr_text`（老人第 1 周自由发言的转写）的保留期限与是否进任何导出。
4. 延迟口径：老人答完到机器人开口约 3–8 秒（ASR 2–4s + 生成 1–2s + 合成 1–2s），
  比句库即答慢。临床上接受与否，真机听过再定。
5. **asr_text 的删除通道**：发声账本是只追加表（禁改禁删，回滚也 fail-closed）——
  第 1 周转写文本因此成了全库唯一「结构上删不掉」的患者言语文本。受试者提出
  删除数据时怎么办，要么设计受控删除通道（类似音频删除回执那套），要么在知情
  同意里写明保留口径。这是设计决定，不是笔误，要拍板。

### 2026-09-03 追加：每问多轮（钱凯「每个问题跟他聊一会」，Eric 拍板默认 2 轮）

老人答完 → 机器人现编一句（带轻追问）→ **系统自动再开麦**让老人接着说 → 机器人再说
一句 → 到上限那一轮只做收束、不再提问 → **自动问下一问**。研究者屏上有轮次提示，随时
可关开关或手点接管；手点句库不触发多轮。上限 `RAPPORT_MAX_ROUNDS`（默认 2，1 = 退回
一问一答）。生成器每轮都拿到本问前几轮的「老人说 / 小语说」，不重复自己说过的话。

- 守卫新增一条：末轮生成句凡是把话头递回老人的一律拒绝（问号，以及「吗/呢/吧/么」结尾、
  「再讲讲…」「说说您的…」这类邀请式说法），回落 k1「好的，谢谢您告诉我。」——末轮之后
  不再开麦，留个问题等于让老人对着空气说话。这道守卫**由端点兜底复核**，不只长在某一个
  生成引擎里。
- **是否续麦按这句自己的内容判，不按来源假设**：AI 现编句用同一个谓词核一遍（模型完全
  可能交回一句纯道谢），句库句用冻结库自带的 `invites_more`。对着一句已经收束的话开麦，
  老人不知道该说什么——那正是钱凯最初报的现象的镜像。
- **续麦不重念问句**：机器人说完追问后重新开麦时停在回应拍，老人屏上仍是小语刚说的
  那句；不会把本问的原问句再念一遍（第一版会，真机走查与复核都抓到）。
- **只有"邀请老人接着说"的句子才续麦**：收束句（j2「那我们聊点别的吧」、k1「好的，谢谢您
  告诉我」）说完直接换下一问，不会出现"说完聊点别的又开麦"这种自相矛盾的指令。
- **同一问最多请老人重说一次**：连续听不清（多为网络/ASR 故障，不是老人的错）第二次即
  收束，不反复要求痴呆老人重复自己。
- **聊满不是报错**：达到轮数上限时机器人仍说一句收束句（一个字节不进云），而不是让老人
  说完什么都没有。
- 「说完再开麦」按句长估时（约 3.5 字/秒 + 起播余量，4–16 秒）；换问后按**下一问的真实
  字数**再估一次（机构环境四问 15–22 字，固定值会在问句念完前开麦）。不是精确同步，真机
  若发现抢话或等太久，改这一个系数即可。
- **自动开麦被放弃时一定留痕**：场次状态变化或录音授权未确认导致这一轮没开麦，研究者屏上
  会有提示与 toast，不会静悄悄回到「老人说完没有回应」。
- 老人端「该念哪一句」只由位置+话拍+发声行决定，**与 wseq 无关**：开麦要重签 wseq，若把它
  算进判据，正在播的那句会被掐断并从头重念，而这一遍发生在麦克风已经打开之后——机器人
  自己的声音会被录进老人的答句，下一轮当成老人说的话送进云端。
- **伦理口径变化**：机器人对老人说的未预审句子从每问 1 句变为最多 N 句；上面第「四」节
  的判断不变，报备时按 N 轮口径。**这是第 6 个拍板点：N 取几、要不要按节不同。**

另：账本行落库在机器人开口**之前**（定稿待说）；是否真读给老人听，以
`ttsserveevidence` 里 `source='rapport_utterance'` 且指向该行的服务证据为准。
