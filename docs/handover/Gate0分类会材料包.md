# Gate 0 分类会材料包

> 这是**下一件必须由人做的事**，工程侧做不了。会议 60–90 分钟，由 PI 组织。
> 会议本身**不等于**这道门通过；它的唯一产出是一页签字索引，把后面每一项的负责人和截止日定下来。
> 依据：收据 187《医院正式使用总门禁》§6。

## 1. 为什么必须先开这个会

在这个会之前，没有任何人有权判定这套系统属于哪一类活动——是可用性研究、观察性研究、
研究者发起的干预试验，还是医疗器械。**开发团队不得自行把"语言/认知训练"认定为"非干预"。**
分类没定，后面的伦理审查路径、备案要求、器械边界、数据处理协议全都无从谈起。

## 2. 建议参会

| 角色 | 为什么必须到 |
| --- | --- |
| PI | 研究方案、目标人群、主要结局的唯一决定人 |
| 临床科室负责人 | 现场责任、医护在场要求、不良事件处置 |
| 伦理委员会秘书处 | 审查路径与所需材料 |
| 临床研究管理部门 | 科学审查、机构立项、是否需要研究登记备案编号 |
| 法务 / 个人信息保护负责人 | 敏感个人信息、单独同意、与云服务商的处理协议 |
| 信息中心 / 数据安全 | 网络边界、分类分级、账户与密钥归属 |
| 医学工程 / 药械管理 | 是否触及医疗器械边界，是否需要分类界定 |
| 采购 / 合同 | 若需与云服务商签正式协议 |

## 3. 会前 30 分钟发给参会人的事实清单（工程侧提供，全部可核）

- **系统现在能做什么**（2026-08-27 核对）：第 2–8 周全部 7 周、每周 78 个计分题位的训练
  内容都已结构化冻结并登记，自动带练在真实场次通道上可以整周跑通（AI 读题 → 自动开麦 →
  录音上传 → 语音识别 → 判定 → 反馈 → 推进），暂停后可双向恢复；老人端有常驻的一键暂停；
  照护员有独立的最小权限工作台。**五份量表（SFACS / GDS-15 / NPI-Q / ACE-III / 动物流畅性）
  可以电子录入，但它们是原型道，不是正式结局契约。**
- **系统现在不能做什么**：不能收真实受试者；两张正式结局量表的定义包尚未由 PI 冻结，
  因此正式量表录入在系统里恒被拒绝；题库冻结目前只有口头口径，书面双签还没补。
  **照护员工作台在结构上只能跑第 2 周 20 题的模拟场次**（两个照护员端点硬绑
  `require_caregiver_operational_demo20`，没有开关）——真实训练场次必须由研究者或
  管理员账号操作。排班前请按这一条估工作量。
- **四条独立的云端数据流**（必须分开审批，不能打包成一句"用了 AI"）：

  | 数据流 | 出机构的是什么 | 工程现状 |
  | --- | --- | --- |
  | 固定批准文本 → 语音合成 | 只有题库/脚本/固定界面话术，白名单闭集，永不携带受试者字段 | 已实现并有运行期守卫 |
  | 受试者录音 → 语音识别 | **原始音频**（含声纹） | 已实现，逐受试者授权后才外呼 |
  | 受试者回答文本 → 大模型判定 | 题面上下文 + **受试者回答文本** | 已实现，结构上不携带画像/姓名/编号 |
  | 量表条目 + 聚合训练统计 → 大模型初评（仅 SFACS） | 量表条目**原文**、等级锚点，以及该受试者的**聚合数字统计**（锁定得分均值、提示层级均值、覆盖周次） | 2026-08-20 起在产。载荷不含编号/姓名/画像，也不含逐题回答文本与时间戳；建议值必须逐项人工核验才能锁定 |

- **数据留在哪**：数据库、录音原件、导出包、语音缓存都在课题组控制的服务器上；
  云端只经手上表四类数据。
- **已有的技术门禁**：具名账号 + 逐场次短时配对码、操作审计链、去标识导出、
  音频删除闸门、每日备份 + 异地副本 + 每周恢复演练。
- **明确没有的东西**：伦理批件、研究登记备案编号、敏感个人信息影响评估、
  与云服务商的数据处理协议、医疗器械分类结论、机构控制的云账户（**当前用的是个人开发密钥**）。

## 4. 会上必须当场定下来的一页（签字索引）

逐项写清楚，每项后面写负责人和截止日：

1. **预期用途与目标人群**（一句话，不含"治疗""康复""延缓"等词，除非确实要按那个路径走）
2. **禁止宣称**（明确列出不得对外说的话）
3. **分类判定**：可用性研究 / 观察性研究 / 研究者发起的干预试验 / 医疗器械临床试验 / 日常诊疗
4. **三条云端数据流各自的批准状态与负责人**（照第 3 节的表逐行判）
5. **数据是否进入正式病历**
6. **录音政策**：逐类/逐题选 必需 / 可选 / 禁止（这项直接决定系统里能不能开录音）
7. **施测时间窗口**：只认排期当天，还是允许"服务器实际启动日 + 宽限期"
8. **试点参数**：人数、科室、时段、是否强制双设备、医护是否必须在场、停止标准、事故联系人
9. **每项后续审批的负责人与截止日**

## 5. 会后必须补齐的三份独立正式意见（缺一，这道门就不算过）

这三份是**独立的书面意见**，一页索引只能作为它们的目录，不能代替它们：

1. **人工智能科技伦理**：由本单位伦理委员会或合格服务中心完成初审并决定后续程序；
   记录编号、版本与跟踪周期，以及模型/用途变更的触发条件。
2. **生成式 AI / 深度合成 / 内容标识 / 算法备案适用性**：由法务与网信责任部门按
   "封闭科研 / 院内服务 / 面向公众"的真实边界书面判断。**不因为有登录限制或有一句
   口头提示就自动排除。**
3. **医疗器械适用性**：明确分类界定路径与申请主体，以及走研究者发起试验还是器械临床试验。
   两条路径**不得混用**。

## 6. 会议不产出什么

- 不产出"可以开始收人"的结论。
- 不产出对上述三份意见的替代。
- 不改变系统里任何一道 fail-closed 门禁——那些要等对应的书面依据到位后，
  由具名负责人按流程放行。

## 7. 会后工程侧会做什么

拿到第 6 项（录音政策）和第 7 项（时间窗口）的书面结论后，工程侧才能把这两条
写进系统的冻结政策文件。**在此之前，工程侧不会也不应该替 PI 预设默认值。**
