# 研究者与管理员操作手册

> 面向要用这套系统带受试者做训练、复核评分、取数据的人。假设你没读过任何代码。
> 照护员在养老院现场只用另一份更短的 `../照护员本机操作指南.md`，两份不要混用。
>
> **先看一句**：系统里所有"点不动""被拒绝"都是设计好的保护。看到就先读提示、
> 再找负责人，**不要想办法绕过去**。绕过去的代价是数据不能用于研究。

## 0. 三个区，先认清自己在哪

登录后顶部有三个标签，整套流程就在这三个区里：

| 区 | 干什么 |
| --- | --- |
| **准备区** | 建受试者档案、核对协议、登记量表、建训练安排 |
| **训练台** | 今天已审核的安排一键开训，现场带着做 |
| **分析后台** | 事后回看 AI 判定与录音、复核锁分、导出数据 |

**训练进行中切换到别的区会弹确认**，这是防误触，不是故障；确认后场次不会丢，切回来还在原处。

## 1. 第一次使用：开账号

账号只能由管理员在服务器上用命令建，**系统里没有自助注册**。找系统负责人开，并说清你要哪种角色：

| 角色 | 能做什么 | 不能做什么 |
| --- | --- | --- |
| `researcher` 研究者 | 建档、排程、开训、复核锁分、看**自己带的**场次 | 看别人带的场次、删录音、登记撤回 |
| `data_steward` 数据管理员 | 审计、完整性核验、去标识导出、**跨受试者的只读研究数据接口** | 建档、开训、改临床事实 |
| `admin` 管理员 | 以上全部 + 账号管理 + 删录音 + 批准延期 | — |
| `caregiver_operator` 照护员 | 只有一个简化工作台（今天任务/开始/暂停/求助/接管/结束） | 其它一切 |

**不要共用账号。** 谁锁的分、谁评的量表、谁删的录音，全部按登录身份记进审计链，
共用账号等于把这条链毁掉。

## 2. 完整流程

### 2.1 准备区：建档

准备区 → 「登记新受试者」。要填的关键项：

- **研究编号**：系统里全程用它，不要填姓名。
- **认知障碍程度**、**普通话资格**：影响能不能开训（不合格会被拒绝，这是设计）。
- **知情同意**：同意状态、类型（本人/代理）、签署人、时间。
- **录音授权**：没有授权，录音相关的一切都开不了。
- **二次利用是否允许**：这是**导出的唯一录入口**，这里没勾，将来导不出去。
- **云处理授权**：要用云端语音识别和判分，必须逐受试者授权并记录告知版本。

准备区顶部还有：**量表抽屉**（前测/后测/随访随时录入）、**量表就绪状态**、
**登记研究撤回**（仅管理员）。

### 2.2 准备区：建训练安排

准备区默认在「真实研究」分区、「研究规范流程」模式。要建安排：

1. 选受试者 → 「创建训练安排」
2. 填周次与日期 → 提交
3. **另一位有权限的人审核通过**后，它才会出现在训练台的今日队列里

旁边有个「快速演练（仅模拟）」，那是给模拟档案用的一键流程，**不能用于真人**。

### 2.3 训练台：开训

训练台显示**今天已审核**的安排。点「开始本次」。

会被拒绝的常见情况，都是设计：

| 提示 | 原因 | 怎么办 |
| --- | --- | --- |
| 「语音服务未准备」 | 管理员还没做 AI 服务合成检查 | 请管理员在模拟场次面板执行一次；照护员不要自己改设置 |
| 第 3–8 周被拒 | 那些周的内容还没冻结 | 等内容组交付，工程侧不能绕 |
| 真实档案被拒 | 题库还是草稿、图片权利未审批 | 见 `七道门现状表.md` 第 1 道门 |
| 已有未收尾场次 | 上一次没收口 | 回去把上一次做完，不要新开 |

开训后：**老人画面要单独开在另一个窗口**（地址以 `/patient` 结尾），
用当次的临时配对 PIN 配对。工作人员页面显示「老人画面已打开」之后才继续。

### 2.4 训练中

- 每个环节都能看到 AI 转写、AI 判类、提示层级；研究者可以随时接管。
- **自动驾驶（AI 自动推进）目前只对合成模拟档案开放**，真实场次走人工模式。
- 老人端常驻「暂停练习」，老人自己按下就立刻停朗读、关麦、丢弃半段录音。
  **暂停之后系统绝不自己继续**，恢复必须由有权限的人按服务器当前状态执行。
- 技术故障（麦克风、上传、识别失败）**不算老人答错，也不消耗提示次数**。

### 2.5 收尾与复核锁分

现场收尾要填收尾表单（必选项没填，服务端会拒存，页面上的「尚未保存」不会消失）。

**锁分在分析后台做，不在现场。** 锁分前系统会强制要求：

1. 具名鉴权「加载并核对录音」——不听录音不让锁；
2. 评分必选；
3. 「确认锁定」二次确认；
4. 所有环节都锁完，才能点「锁定复核并最终完成」。

**锁定之后不可改**，这是研究护栏。发现锁错了，找 PI 与丁老师定更正口径，
不要自己想办法改。

### 2.6 正式评估（量表）

准备区/队列里有「正式评估」独立工作流。**它目前是只读的**：两张正式量表的
定义包尚未由 PI 冻结，系统里的正式录入被门禁封锁，页面会明说。

PI 把三份文件交付后（见 `Gate0分类会材料包.md` 与
`scripts/check_pi_content_package.py`），队列每行会出现「打开执行」，
上方也会出现「新建正式评估」。在此之前那两个入口不会显示——**不是坏了**。

### 2.7 导出与取数

- **页面上看数据**：分析后台逐场次回看；要跨受试者看全貌，点分析后台顶部的
  「打开研究数据总览」（需要数据管理员或管理员账号）。
- **导出去标识包**：分析后台的导出流程。需要服务器已配置去标识密钥，
  且该受试者勾了「二次利用允许」。导出包里的录音副本**始终按敏感数据管理**，
  不属于去标识包。
- **程序化取数**：见 `研究数据接口使用说明.md`（需要 `data_steward` 或 `admin` 账号）。

## 3. 管理员额外要做的事

### 3.1 每次开训前的 AI 服务检查

管理员在模拟场次面板点「执行 AI 服务合成检查」。它只用固定话术"您好"，
**不读任何受试者数据、不保存合成音频与识别文字**。检查过期或配置变了，
自动驾驶会在取得控制权前直接拒绝——这是设计。

### 3.2 账号与密钥

- 建账号、改密、停用：服务器命令行，找系统负责人。
- **停用账号会立刻吊销该账号的全部会话**。
- 云 API 密钥、去标识密钥：只在服务器上配置，**任何人不要贴进聊天或邮件**。

### 3.3 数据边界（每天都要记得）

| 会离开机构的 | 不会离开机构的 |
| --- | --- |
| 固定话术文本 → 云端语音合成（白名单闭集，**永不携带受试者字段**） | 受试者档案、姓名、编号 |
| 受试者录音 → 云端语音识别（**含声纹**） | 录音原件（正本留在服务器） |
| 受试者回答文本 → 云端判分（结构上不含画像/姓名/编号） | 画像（只在老人端本地，永不上传，也永不进判分） |

**不要把"数据存在我们自己的服务器上"说成"所有数据都不上云"。**
启用云端识别和判分时，音频和回答文本确实会出机构。

## 4. 出问题时

| 现象 | 怎么办 |
| --- | --- |
| 按钮是灰的 | 说明条件还没满足，读旁边的提示；不要刷新页面试图绕过 |
| 「这一步还没有确认」 | 等页面自动核对，不要反复点；长时间不变找负责人 |
| 「正在重新确认状态」 | 保持页面打开；老人不适时先照顾老人 |
| 页面报错屏 | 点「重载」；反复出现就截图找负责人 |
| 老人不适 | **先照顾老人**，再处理页面 |

## 5. 这份手册没有截图

系统的界面细节会随版本变化，贴过时的截图比不贴更坏。
真机验收（见 `真机验收记录表.md`）时会在目标设备上逐屏留证，
那批截图带设备型号、浏览器版本和日期，才是可以拿去培训的材料。

## 6. 当前状态

**这套系统目前不能给真实老人正式使用。** 工程侧该做的基本做完了，
卡住的是内容冻结、伦理批件、隐私评估、真机验收和养老院接收——
每一项的判定人都在外部。逐项现状见 `七道门现状表.md`。
