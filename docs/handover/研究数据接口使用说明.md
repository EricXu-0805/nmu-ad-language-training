# 研究数据接口使用说明（给 PI 与合作者）

> 面向要取数做统计的人。三段：**怎么看**、**怎么调**、**SPSS/R 怎么读**。
> 最后一节是必须先知道的边界，跳过会得出错误结论。

## 0. 先知道三件事

1. **接口出的是去标识数据。** 受试者、场次、录音都换成了假名（`SUBJ-…`、`SESS-…`），
   真实研究编号、姓名、知情同意签署人**永远不会**出现。这不是可以配置的选项。
2. **作答文本不出接口。** 语音识别原文、人工确认文本、AI 判分理由、现场备注一律不出。
   要看原文只能在系统里逐条回看，且会留审计记录。
3. **没有绝对时间。** 只有时长、潜伏期和序号这类相对量。需要"第几天"这种派生列，
   要先经 PI 批准再由工程加，不能自己从别处凑。

## 1. 怎么看（页面）

有两个入口，看你要看什么：

**逐场次回看**：登录 → 分析后台 → 点某位受试者 → 点某个场次。
能看 AI 判定、提示层级、人工锁定分和录音。**这一屏看得到真实研究编号**
（研究者本来就要按编号找人）。

**跨受试者看全貌**：登录 → 分析后台 → **「打开研究数据总览」**。
这一屏和下面第 2 节的接口是同一份数据、同一份去标识投影，只是给你一个能翻页的表格，
再加两个按钮：「导出本页 CSV」和「导出数据字典 CSV」。
需要 data_steward 或 admin 账号，研究者账号点进去会明确告诉你角色不够。

这一屏**看不到**真实研究编号——它渲染的只有接口自己声明的那些列，
结构上取不到别的东西。所以"屏上看到的"和"导出的"不可能不一样。
页脚常驻假名密钥编号，两次导出能不能 join 就看它一样不一样。

导出的是**当前这一页**（默认 200 行）。要全量请照第 2 节按游标逐页拉。

## 2. 怎么调（程序化取数）

### 谁能调

需要一个 **数据管理员（data_steward）或管理员（admin）** 角色的账号。
普通研究者账号（researcher）**故意不给**——它按 trainer_id 隔离，只能看自己带的场次；
跨受试者的只读属于数据治理面，需要单独授权。找系统负责人开账号。

> 目前还没有"只读 API 令牌"，程序化取数需要先用账号登录拿到会话。
> 只读令牌在路线图上（可撤销、只允许 GET、只允许 `/research/v1/*`），
> 但它涉及数据库结构变更，要等负责人回来后一并做。

### 端点

所有端点都是 GET，没有任何写入口。

| 端点 | 内容 |
| --- | --- |
| `/research/v1/meta` | 接口是否就绪、有哪些数据集、分页参数。**密钥没配时它也能读**，用来自诊 |
| `/research/v1/dictionary` | 数据字典（每一列的类型、含义、是否假名） |
| `/research/v1/dictionary.csv` | 同上，CSV |
| `/research/v1/subjects` | 一行一位受试者 |
| `/research/v1/sessions` | 一行一个训练场次 |
| `/research/v1/turns` | 一行一个（场次，题目，环节）——**统计主力表** |
| `/research/v1/<数据集>.csv` | 同一份投影的 CSV |

### 必填与可选参数

- `data_classification`：**必填，没有默认值**。取 `research`（真实研究）或 `simulation`（模拟）。
  没有默认是刻意的——把模拟数据混进真实结论是这套系统最不能出的错。
- `cursor`：翻页用，从上一页响应里的 `next_cursor` 原样带回来。
- `limit`：每页行数，1–1000，默认 200。

**写了契约没实现的参数会被拒绝**（返回 422），不会被静默忽略。

### 翻页

用游标而不是页码。页码在有人同时写入时会漏行或重行，而研究取数最不该出现的
就是"每次拉到的行数不一样"。

```bash
# 第一页
curl -sS -b cookies.txt 'https://<站点>/research/v1/turns?data_classification=research'
# 响应里如果 has_more 为 true，把 next_cursor 原样带回去
curl -sS -b cookies.txt 'https://<站点>/research/v1/turns?data_classification=research&cursor=<next_cursor>'
```

### Python 取全量

```python
import requests

BASE = "https://<站点>"
session = requests.Session()
session.post(f"{BASE}/auth/login", json={"username": "...", "password": "..."})

def fetch_all(dataset, classification="research"):
    rows, cursor = [], None
    while True:
        params = {"data_classification": classification, "limit": 1000}
        if cursor:
            params["cursor"] = cursor
        payload = session.get(f"{BASE}/research/v1/{dataset}", params=params).json()
        rows.extend(payload["rows"])
        if not payload["has_more"]:
            return rows, payload["pseudonym_key_id"]
        cursor = payload["next_cursor"]

turns, key_id = fetch_all("turns")
```

### R 读 CSV

```r
# 先用浏览器登录后另存，或用 httr 带上会话 cookie
turns <- read.csv("nmu-turns-research.csv", fileEncoding = "UTF-8-BOM")
```

CSV 带 BOM 是刻意的：Windows 上的 Excel 和 SPSS 不看 BOM 就按本地代码页解，
中文列名会乱码。

## 3. 表之间怎么连

- `turns.session_code` → `sessions.session_code`
- `sessions.subject_code` → `subjects.subject_code`
- 同一环节的自然键是 `(session_code, item_id, turn_seq)`——**不要用数据库行号**，
  接口里根本没有行号。撤回受试者的墓碑行**也保留这三列**，所以这个键在整张表上唯一，
  `distinct()` 不会把墓碑塌成一行。

**假名与去标识导出包完全一致**，所以用接口拉的表可以直接和导出的 CSV 批次 join。

## 4. 必须先知道的边界

### 4.1 换过密钥的数据不能混着用

假名由服务器上的去标识密钥生成。**密钥一旦轮换，所有假名全部改变**，
旧 CSV 和新拉取**无法 join**，而且不会有任何报错——你会得到两批看似不同的人。

唯一的检测手段是每次响应里的 `pseudonym_key_id`：**做分析前先核对两批数据的这个值是否相同**。
不同就不要合并，找系统负责人。

### 4.2 撤回的受试者会留一行空记录

登记了研究撤回的受试者，在**三张表里都仍然有一行**，但内容为空、`withdrawn` 为真。
这是刻意的：如果直接消失，两次拉取的差就成了"谁撤回了"的旁路。

**统计时按 `withdrawn` 过滤，不要按"这次没出现"判断。** 三张表都有这一列，
在训的人是 `false` 而不是空值——所以 `filter withdrawn = 0` 不会连在训的人一起滤掉。

墓碑行保留的东西，按表不同：

| 表 | 墓碑行里还有什么 | 为什么 |
| --- | --- | --- |
| `subjects` | `subject_code`、`withdrawn`、`session_count` | 场次数留着，分母才稳；临床属性（含 `secondary_use_allowed`）全部清空——撤回的人不该还在声称可以二次利用 |
| `sessions` | `session_code`、`subject_code`、`withdrawn`、`pseudonym_key_id` | 场次数与受试者的对应关系是分母的一部分 |
| `turns` | `session_code`、`subject_code`、`item_id`、`turn_seq`、`withdrawn` | **自然键必须留**，否则一个 36 环节的场次会返回 36 行一模一样的行，`distinct()` 一跑分母从 36 变 1 |

### 4.3 正式结局量表目前是空的

两张正式量表的定义包尚未由 PI 冻结，系统里的正式量表录入是被门禁封锁的，
所以量表数据现在为零。历史上有一批自由格式的旧量表记录，它们**不是**正式研究结局，
接口不会把它们冒充成结局输出。

### 4.4 `judge_portrait_used` 恒为 false

这一列不是分析变量，是审计证据：它证明判分过程从未使用受试者画像。
如果哪天它出现 true，说明有人破坏了「画像不进判分」这条硬约束，请立刻上报。

### 4.5 AI 分不是研究真值

`ai_score` 是实时运营用的初评，`reviewed_score` 才是人工复核锁定的研究真值。
`score_locked` 为真才代表这一格已经定稿。**不要用 `ai_score` 做主要结局分析。**

### 4.6 生产上不开 API 文档页

`/docs`、`/redoc`、`/openapi.json` 在生产环境固定返回 404，这是发布前检查的红线之一
（它们会把整个接口结构暴露给未登录的人）。要看接口结构就看这份文档和
`/research/v1/dictionary`。

## 5. 出问题时

| 返回 | 含义 | 怎么办 |
| --- | --- | --- |
| 401 | 没登录或会话过期 | 重新登录 |
| 403 | 账号角色不够 | 找负责人确认账号角色（需要 data_steward 或 admin） |
| 404 `research_dataset_unknown` | 数据集名写错 | 看 `/research/v1/meta` 里的 `datasets` |
| 422 `research_query_invalid` | 用了没实现的参数 | 只用上面列出的三个参数 |
| 422 `research_cursor_invalid` | 游标被改过或过期 | 从第一页重新开始 |
| **503 `research_deidentification_unavailable`** | **服务器没配去标识密钥** | 找系统负责人配置；在此之前接口一行也不会返回，这是刻意的 |
