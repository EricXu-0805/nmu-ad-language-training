# 研究数据接口使用说明（给 PI 与合作者）

> 面向要取数做统计的人。三段：**怎么看**、**怎么调**、**SPSS/R 怎么读**。
> 最后一节是必须先知道的边界，跳过会得出错误结论。

## 0. 先知道三件事

1. **接口出的是去标识数据。** 受试者、场次、录音都换成了假名（`SUBJ-…`、`SESS-…`），
   真实研究编号、姓名、知情同意签署人**永远不会**出现。这不是可以配置的选项。
2. **作答文本不出接口。** 语音识别原文、人工确认文本、AI 判分理由、现场备注一律不出。
   要看原文只能在系统里逐条回看，且会留审计记录。
3. **没有绝对时间。** 只有时长、潜伏期和序号这类相对量。需要"第几天"这种派生列，
   要先经 PI 批准再由工程加，不能自己从别处凑。

## 1. 怎么看（页面）

有两个入口，看你要看什么：

**逐场次回看**：登录 → 分析后台 → 点某位受试者 → 点某个场次。
能看 AI 判定、提示层级、人工锁定分和录音。**这一屏看得到真实研究编号**
（研究者本来就要按编号找人）。

**跨受试者看全貌**：登录 → 分析后台 → **「打开研究数据总览」**。
这一屏和下面第 2 节的接口是同一份数据、同一份去标识投影，只是给你一个能翻页的表格，
再加两个按钮：「导出本页 CSV」和「导出数据字典 CSV」。
需要 data_steward 或 admin 账号，研究者账号点进去会明确告诉你角色不够。

这一屏**看不到**真实研究编号——它渲染的只有接口自己声明的那些列，
结构上取不到别的东西。所以"屏上看到的"和"导出的"不可能不一样。
页脚常驻假名密钥编号，两次导出能不能 join 就看它一样不一样。

导出的是**当前这一页**（默认 200 行）。要全量请照第 2 节按游标逐页拉。

## 2. 怎么调（程序化取数）

### 谁能调

需要一个 **数据管理员（data_steward）或管理员（admin）** 角色的账号。
普通研究者账号（researcher）**故意不给**——它按 trainer_id 隔离，只能看自己带的场次；
跨受试者的只读属于数据治理面，需要单独授权。找系统负责人开账号。

> 目前还没有"只读 API 令牌"，程序化取数需要先用账号登录拿到会话。
> 只读令牌在路线图上（可撤销、只允许 GET、只允许 `/research/v1/*`），
> 但它涉及数据库结构变更，要等负责人回来后一并做。

### 端点

所有端点都是 GET，没有任何写入口。

| 端点 | 内容 |
| --- | --- |
| `/research/v1/meta` | 接口是否就绪、有哪些数据集、分页参数。**密钥没配时它也能读**，用来自诊 |
| `/research/v1/dictionary` | 数据字典（每一列的类型、含义、是否假名） |
| `/research/v1/dictionary.csv` | 同上，CSV |
| `/research/v1/subjects` | 一行一位受试者 |
| `/research/v1/sessions` | 一行一个训练场次 |
| `/research/v1/turns` | 一行一个（场次，题目，环节）——**统计主力表** |
| `/research/v1/questionnaire_records` | 一行一份已锁定的量表记录（含总分与判定档） |
| `/research/v1/questionnaire_item_values` | 一行一个（记录，条目，字段）；用 `record_code` 与上一张表 join |
| `/research/v1/<数据集>.csv` | 同一份投影的 CSV |

### 真实研究分区只发「冻结版本」

`data_classification=research` 拉到的**不是库里当下的一切**，而是最近一次
**切纪元**冻住的那批场次。切纪元是一个治理动作：由数据管理员与管理员两个具名的人
各跑一次 `scripts/cut_quality_release.py`（一个提议、另一个拿着 sha256 批准）。
没切过就一行都拿不到，而不是先给一份粗略的。

对取数的人有四个直接后果：

1. **同一个纪元、同一页的成功响应正文逐字节相同。** 切纪元时三张公开行表已经
   物化成不可变快照；之后修改档案、终态、复核分或新增环节，都不会改写旧纪元。
   分页游标也由纪元、数据集与冻结行序号确定，不再每次随机变化。429 限速响应和
   HTTP 日期等传输头不属于这份冻结数据正文。
2. **每一页都带一个 `release` 字段**，里面是 `epoch_seq`（第几版）、
   `cohort_rule_version`、`aggregate_payload_sha256`。**两份数据只有 `epoch_seq`
   相同才能直接比对**；纪元号不同就是两批场次，行数对不上是正常的。
3. **CSV 文件名带纪元号**（`nmu-turns-research-epoch003.csv`）。存盘之后
   `release` 字段就不在了，文件名是唯一留住版本的地方，**不要改名**。
4. **要拿到新数据，只能再切一次纪元**，不能靠多等一会儿再拉一次。

`/research/v1/meta` 里的 `research_release` 会告诉你现在绑在第几版、队列里有多少
场次、截止时刻是什么时候；没绑上时它给出拒绝码与一句人话。**绝对时刻只出现在
meta，数据面上一个都没有**——那是这个接口的红线。

`simulation` 分区不绑纪元（那里没有真人），`release` 恒为 `null`。

### 必填与可选参数

- `data_classification`：**必填，没有默认值**。取 `research`（真实研究）或 `simulation`（模拟）。
  没有默认是刻意的——把模拟数据混进真实结论是这套系统最不能出的错。
- `cursor`：翻页用，从上一页响应里的 `next_cursor` 原样带回来。
- `limit`：每页行数，1–1000，默认 200。

**写了契约没实现的参数会被拒绝**（返回 422），不会被静默忽略。

### 翻页

用游标而不是页码。真实研究分区的游标指向冻结快照的行序号；仿真分区仍用活数据
的加密自然键游标。游标不能跨数据集、跨纪元或跨分区使用。

```bash
# 第一页
curl -sS -b cookies.txt 'https://<站点>/research/v1/turns?data_classification=research'
# 响应里如果 has_more 为 true，把 next_cursor 原样带回去
curl -sS -b cookies.txt 'https://<站点>/research/v1/turns?data_classification=research&cursor=<next_cursor>'
```

### Python 取全量

```python
import time
import requests

BASE = "https://<站点>"
session = requests.Session()
login = session.post(
    f"{BASE}/auth/login", json={"username": "...", "password": "..."})
login.raise_for_status()

def fetch_all(dataset, classification="research"):
    rows, cursor, release = [], None, None
    while True:
        params = {"data_classification": classification, "limit": 1000}
        if cursor:
            params["cursor"] = cursor
        response = session.get(
            f"{BASE}/research/v1/{dataset}", params=params)
        if response.status_code == 429:
            # 全量 17 页以上会超过突发额度；必须尊重服务端的 Retry-After，
            # 不能把 429 当成一页 JSON 数据继续索引。
            retry_after = response.headers.get("Retry-After", "")
            if not retry_after.isdigit() or not 1 <= int(retry_after) <= 60:
                raise RuntimeError("服务端限速但没有给出可执行的 Retry-After")
            time.sleep(int(retry_after))
            continue
        response.raise_for_status()
        payload = response.json()
        # 翻页途中换了版就重来：混着两版拉下来的数据既不是第 N 版也不是第 N+1 版，
        # 比拉不到更糟。正常操作下不会发生（切纪元要求当时没有场次开着）。
        if release is not None and payload["release"] != release:
            raise RuntimeError("翻页途中冻结版本变了，请从第一页重新拉")
        release = payload["release"]
        rows.extend(payload["rows"])
        if not payload["has_more"]:
            return rows, payload["pseudonym_key_id"], release
        cursor = payload["next_cursor"]

turns, key_id, release = fetch_all("turns")
print("这份数据是第", release["epoch_seq"], "版")
```

## 3. 表之间怎么连

- `turns.session_code` → `sessions.session_code`
- `sessions.subject_code` → `subjects.subject_code`
- 同一环节的自然键是 `(session_code, item_id, turn_seq)`——**不要用数据库行号**，
  接口里根本没有行号。撤回受试者的墓碑行**也保留这三列**，所以这个键在整张表上唯一，
  `distinct()` 不会把墓碑塌成一行。

**假名与去标识导出包完全一致**，所以用接口拉的表可以直接和导出的 CSV 批次 join。

这一节说的是**导出的 CSV 包**，不是上面的接口。2026-08-30 上线之前写的读取脚本，
以下三处会读不到或读错。

**`item_scores.csv`：结局指标从一个字符串拆成了一列一个。**

要自己写正则拆，拆错了不报错。现在七个指标各占一列：`n`、`naming_accuracy`、
`spontaneous_naming_accuracy`、`prompt_rate`、`total_prompt_load`、
`avg_time_per_item`、`total_task_time`，加上关系识别那两项
`weekly_de_score_percentile`、`spontaneous_relation_identification_rate`、
`weekly_me_score_percentile`。

**同时补回了一样以前根本没落盘的东西**：提示层级分布。旧代码把嵌套结构直接丢掉
（`_flat` 只留标量），所以"这个人有多依赖提示"的证据从来没进过导出包，想复原只能
在 R 里把判分引擎重写一遍。现在是 `prompt_level_0` 到 `prompt_level_3` 四列。
逐题明细另出 `per_item_json` / `per_item_de_total_json` 两列（JSON 字符串）。

**所有表的表头现在从契约来，不从数据推。**
旧代码是 `cols = sorted({k for r in rows for k in r}) if rows else []`——**没有异常

炸，要么被 `dplyr::bind_rows` 静默跳过；而"异常事件为零"恰恰是最常见的情况，被跳过的

列序固定。

**`turns.csv` 多一列 `duration_seconds`；`questionnaire_records.csv` 多两列
`phase_ordinal` / `superseded_by_ordinal`**（见 §4 的同期别重测那条）。

## 4. 必须先知道的边界

### 4.1 换过密钥的数据不能混着用

假名由服务器上的去标识密钥生成。**密钥一旦轮换，所有假名全部改变**，
旧 CSV 和新拉取**无法 join**，而且不会有任何报错——你会得到两批看似不同的人。

唯一的检测手段是每次响应里的 `pseudonym_key_id`：**做分析前先核对两批数据的这个值是否相同**。
不同就不要合并，找系统负责人。

### 4.2 撤回以切纪元时刻为界

切纪元前已经登记撤回的受试者不会进入新纪元。切纪元后才登记的撤回**不会动态改写
旧纪元**；否则同一纪元的行会变化，撤回本身也会成为可轮询的单人信号。它会在下一次
切纪元时生效。已经下载到研究人员电脑的文件也不会由平台自动追回，必须按批准的
撤回与已交付副本处置流程执行。

`withdrawn` 列仍保留在固定契约中，用于读取历史迁移形成的墓碑快照；
**统计时按 `withdrawn` 过滤**。但不要用“某人这次没有出现”推断撤回，跨纪元成员变化还有隔离期、完整性
门禁等其他原因。

### 4.3 量表：正式结局是空的，试用道有数据（两件事，别混）

**正式结局量表**：两张正式量表的定义包尚未由 PI 冻结，正式量表录入被门禁封锁，
所以**正式结局数据为零**。历史上有一批自由格式的旧量表记录，它们**不是**正式研究结局，
接口不会把它们冒充成结局输出。

**试用道量表**（SFACS / GDS-15 / NPI-Q / ACE-III / 动物流畅性）：**有数据，可以取**。
2026-08-27 起走 `questionnaire_records` 与 `questionnaire_item_values` 两个数据集，
用 `record_code` 互相 join，也各带 `subject_code` 可直接按人聚合。在此之前它们只在
逐场次导出包里，而且按受试者取数不按场次——同一份量表会在该受试者**每一个**场次的
包里各出现一份，30 人拿前后测要对约 240 个包逐个导出、拼起来、按 `record_code` 去重；
谁忘了去重 n 就放大 8 倍，而重复行的 `computed_total` 完全一致、看不出异常。

三条必须知道的口径：

1. **只发已锁定的记录。** `draft` 还不是证据，接口一行都不发。
2. **改错的做法是新建一条，所以同一期别可能有多行。** 用 `phase_ordinal`
   （同组内序号）和 `superseded_by_ordinal`（作废本条的那条的序号）区分：
   **分析前先滤掉 `superseded_by_ordinal` 非空的行**。取 first 或 max 都可能取到
   作废那条，而两行的总分都是合法值，从数据本身看不出异常。
3. **冻结纪元的口径是「这批场次对应的受试者、且当时已锁定的记录」。**
   纪元是一个场次集合，而量表挂在受试者上；冻结时行被快照成字节，后续读回放快照，
   所以同一个纪元反复读永远得到同一批行。

施测备注、AI 理由、锁定人、锁定时间**永不出接口**——它们在数据字典里被显式标成
`forbidden`，让人看见是被排除了，而不是忘了做。

### 4.4 `judge_portrait_used` 恒为 false

这一列不是分析变量，是审计证据：它证明判分过程从未使用受试者画像。
如果哪天它出现 true，说明有人破坏了「画像不进判分」这条硬约束，请立刻上报。

### 4.5 AI 分不是研究真值

`ai_score` 是实时运营用的初评，`reviewed_score` 才是人工复核锁定的研究真值。
`score_locked` 为真才代表这一格已经定稿。**不要用 `ai_score` 做主要结局分析。**

### 4.6 生产上不开 API 文档页

`/docs`、`/redoc`、`/openapi.json` 在生产环境固定返回 404，这是发布前检查的红线之一
（它们会把整个接口结构暴露给未登录的人）。要看接口结构就看这份文档和
`/research/v1/dictionary`。

## 5. 出问题时

| 返回 | 含义 | 怎么办 |
| --- | --- | --- |
| 401 | 没登录或会话过期 | 重新登录 |
| 403 | 账号角色不够 | 找负责人确认账号角色（需要 data_steward 或 admin） |
| 404 `research_dataset_unknown` | 数据集名写错 | 看 `/research/v1/meta` 里的 `datasets` |
| 422 `research_query_invalid` | 用了没实现的参数 | 只用上面列出的三个参数 |
| 422 `research_cursor_invalid` | 游标被改过或过期 | 从第一页重新开始 |
| **503 `research_deidentification_unavailable`** | **服务器没配去标识密钥** | 找系统负责人配置；在此之前接口一行也不会返回，这是刻意的 |
| **503 `research_release_not_frozen`** | **真实研究分区还没有可发布的冻结版本**（没开冻结发布，或一次纪元都没切过） | 由数据管理员与管理员两个人跑一次切纪元。仿真分区不受影响 |
| 503 `research_release_snapshot_missing` | 当前是升级前的旧纪元，没有真正冻结三张行表 | 重新执行一次提议与批准；不得用当前活表伪造历史快照 |
| 503 `research_release_snapshot_corrupt` | 冻结清单、行数、序号或行摘要不一致 | 立即停止取数，保留现场并由管理员检查数据库与备份；不要重写旧纪元 |
| 503 `research_release_key_rotated` | 去标识密钥换过了，旧纪元的假名与新密钥对不上 | 重新切一次纪元。**换密钥之后所有假名都变了，旧 CSV 无法与新拉取 join** |

上面三条 `research_release_*` **只影响 `data_classification=research`**。拿不准是
哪一道闸的话，先读 `/research/v1/meta` 的 `research_release`，它给出的码与原因就是
接口自己的判断。
